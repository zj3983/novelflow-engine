# 题材角色状态与大纲检查点设计

## 目标

解决两个相互独立但都影响开书稳定性的问题：

1. 非网游角色卡不再使用“现实状态/游戏状态”双线结构，只显示和传递通用“当前状态”。
2. 开书大纲的总纲、角色卡、前十章细纲分别生成和保存，失败时只重跑当前步骤。

## 角色状态模型

### 题材边界

- 网游题材保留 `real_state` 和 `game_state`，分别记录现实线与游戏线。
- 非网游题材使用 `current_state`，记录位置、情绪、身体或境界状态、当前目标和近期明确变化。
- 非网游写作上下文不得出现 `real_state`、`game_state`、现实线或游戏线术语。

### 兼容迁移

- 读取旧非网游角色卡时，将已有 `real_state` 映射为 `current_state`。
- 若旧卡同时存在 `current_state` 和 `real_state`，以 `current_state` 为主，只补充缺失字段和不重复的近期变化。
- 非网游保存后只持久化 `current_state`，删除旧 `real_state` 和误入的 `game_state`。
- 网游项目不执行该迁移，继续保存双线状态及旧游戏面板兼容镜像。

### 页面与写作上下文

- 非网游角色卡页面显示“当前状态”，编辑 `current_state`。
- 网游角色卡页面显示“现实状态”和“游戏状态”。
- 场景角色卡投影：非网游只输出一个通用状态上下文；网游按现实、游戏或切换场景输出对应状态。
- 静态身份、来历、职业、性格和长期动机仍留在角色主档，不复制进动态状态。

## 大纲分步生成

### 三个检查点

1. `outline_foundation`：完整总纲和全部核心卷，不含角色卡和章节细纲。
2. `character_roster`：4 至 6 张开篇角色卡，必须与总纲中的阶段对手和长期反派一致。
3. `chapter_window`：目标章节细纲，初次开书为第 1 至 10 章。

每个检查点独立保存到项目的计划目录，并记录状态、开始时间、完成时间、模型和错误。只有当前步骤校验通过后，才允许进入下一步。

### 恢复规则

- 重试默认从第一个缺失或失败的检查点开始。
- 已成功的检查点不重复调用模型，除非用户明确选择“从此步重新生成”。
- 新检查点写入采用临时文件加原子替换，失败不能覆盖已有可用文件。
- 三步全部通过后，再一次性合并为正式 `outline.json`、角色卡和项目状态。
- 合并失败保留三个检查点，修复后可直接重试合并，不重新调用模型。

### 工作台反馈

工作台显示三个固定步骤及其状态：等待、生成中、已完成、失败。每步可以查看实际输入摘要、输出产物、耗时和错误；失败步骤提供“重试本步”，已完成步骤提供“重新生成此步”。

## 错误处理

- 模型返回的可选非法套路节拍继续清空为 `null`，不让非关键字段废弃整份大纲。
- 缺少总纲必填字段、角色层级不全、章节数量不符等结构错误仍阻止当前检查点完成。
- 题材状态迁移必须幂等，多次读取和保存不能重复近期变化。
- API 返回具体阶段和错误原因，不使用单一的“生成失败”覆盖原始错误。

## 测试范围

- 非网游旧 `real_state` 到 `current_state` 的迁移、合并、保存和写作投影。
- 网游双线状态保持不变。
- 非网游页面不出现“现实状态/游戏状态”，网游页面仍显示两者。
- 三个检查点依次保存、失败恢复、单步重试、最终原子合并。
- 已完成检查点在重试时不再次调用模型。
- 玄幻真实开书回归：总纲、角色卡和前十章细纲可见，且无网游状态术语。

## 不包含

- 不调整角色卡其他静态侧写字段。
- 不改变网游账本、游戏面板和现实余额逻辑。
- 不在本次改动中更换模型或压缩大纲内容规模。
