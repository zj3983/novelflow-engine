# 综合审稿设计

## 目标

底层检查器继续负责篇幅、连续性、题材规则、对话、文风和 AI 味检查，对用户和写手只输出一份综合审稿结果，避免同一问题由读者、编辑和审稿 Agent 重复表达。

## 输出

综合审稿包含状态、分类计数、最多三项主要问题和最多三条修改指令。状态分为通过、需要修改、存在硬伤。硬伤阻止章节通过；对话、正文和 AI 味只触发定向修改，不单独阻止保存。

每项主要问题包含分类、严重程度、问题说明和可执行修改。相同文本直接去重；同类近似问题按规范化关键词合并，优先级依次为硬伤、对话、AI 味、正文。

## 数据流

现有检查器照常并行执行。`build_simplified_review` 收集顶层与嵌套报告，生成唯一的 `simplified_review`。自动改稿只接收综合审稿的修改指令，不再拼接读者、编辑和审稿 Agent 的全部明细。前端只展示综合结果，内部明细仍保存在质量报告中供排查。

## 边界

不删除现有检查器，不增加 LLM 调用，不改变连续性和篇幅硬门禁。本次只收敛报告、改稿输入和页面展示。
