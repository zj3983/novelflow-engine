# 三级大纲模块设计

## 目标

为文件小说项目补齐可编辑、可持久化、会实际参与生成的三级大纲：总纲、阶段大纲和章节大纲。大纲从世界观数据中独立出来，生成第 N 章时只读取与第 N 章有关的内容，避免提示词过长和剧情只围着当前一章打转。

## 当前问题

- 大纲页面实际编辑的是 `world_blueprint.current_arc`、`current_focus` 和 `opening_arc.chapter_beats`，没有完整总纲。
- 世界观、禁写项、当前焦点和章节节拍混在同一份数据中，职责不清。
- 数据库项目已有 `NovelOutline`，文件项目却没有接入，形成两套互不相通的大纲。
- 写作包主要读取当前焦点和开篇节拍，无法稳定知道全书方向及当前阶段的结束目标。

## 数据结构

三级大纲统一存放在文件项目的独立 `outline` 数据中，不再新增第三套大纲概念。

### 总纲

一本书只有一份，字段包括：

- 核心故事：这本书讲什么。
- 主角目标：主角长期想得到或解决什么。
- 主线冲突：持续阻碍主角的力量或问题。
- 成长路线：能力、身份、关系或认知如何变化。
- 结局方向：只规定方向，不要求提前写死具体场面。

### 阶段大纲

一本书可以有多个阶段，每个阶段包含：

- 阶段 ID 和名称。
- 起止章节。
- 阶段目标。
- 主要阻碍。
- 关键兑现。
- 阶段结束时的状态变化。

阶段可以对应分卷，也可以只是若干章组成的小阶段，不强制所有小说使用正式卷名。

### 章节大纲

每章最多一份，字段包括：

- 章节号和暂定标题。
- 本章目标。
- 主要阻碍。
- 主角行动。
- 关键转折。
- 本章兑现。
- 章末钩子。

章节大纲只规定剧情功能，不直接写正文句子，不保存风格规则、人物卡或世界设定。

## 页面设计

保留独立“大纲”页面，使用三个标签：`总纲`、`阶段大纲`、`章节大纲`。

- 总纲页是单份表单。
- 阶段大纲页按章节范围排列，可新增、编辑和删除阶段。
- 章节大纲页按章节号排列，可新增、编辑和删除单章提纲。
- 页面顶部统一显示保存状态，并提供一个保存按钮。
- 世界规则和禁写项继续留在世界观或作者约束页面，不在大纲页面重复出现。

## 保存与兼容

- API 提供文件项目大纲的读取和更新接口。
- 保存时校验章节号为正整数，阶段范围不能倒置，同一章节不能有两份章节大纲。
- 旧项目首次读取时进行非破坏性兼容：
  - `seed_outline` 作为总纲的核心故事初值。
  - `world_blueprint.current_arc` 作为第一个阶段的目标初值。
  - `opening_arc.chapter_beats` 转成对应章节大纲的标题、兑现和钩子。
- 兼容结果只有在用户保存后才写回新结构，原字段暂时保留，避免旧读取路径立即失效。

## 生成读取规则

生成第 N 章时，组装一个精简的 `outline_context`：

1. 始终读取总纲。
2. 只读取章节范围覆盖 N 的阶段大纲。
3. 只读取第 N 章的章节大纲。
4. 若第 N 章没有章节大纲，则使用总纲和当前阶段规划本章，不自动伪造长期大纲。

`outline_context` 先进入剧情规划和推演，再由它们生成写作所需的本章剧情合同。正文写手不接收整本章节列表。

大纲优先级为：章节大纲 > 当前阶段大纲 > 总纲。世界事实、人物状态和已写正文不能被大纲覆盖；发生冲突时应报告冲突，而不是强行执行旧大纲。

## 模块边界

- 大纲模块：决定故事往哪里走。
- 世界观模块：决定世界允许什么、如何运行。
- 人物卡模块：决定人物为什么这样行动和说话。
- 当前状态与记忆：记录已经发生了什么。
- 剧情推演：结合以上输入，决定本章具体发生什么。
- 写作模块：把本章剧情写成正文。

## 错误处理

- 总纲为空时页面显示明确提示，继续生成前由现有流程决定是否阻止，不静默补写总纲。
- 阶段范围重叠时允许保存，但页面提示冲突；生成时选择起始章节最接近当前章的阶段。
- 数据损坏或字段缺失时回退为空结构，并保留原始项目数据，不导致项目打不开。

## 测试

- 单元测试三级大纲的旧数据兼容、保存校验和当前章节选择。
- API 测试文件项目大纲的读取和更新。
- 写作包测试只包含总纲、当前阶段和当前章节，不包含无关章节。
- 前端测试三个标签的显示、编辑和保存。
- 回归测试现有项目页面、世界观页面和章节生成不因迁移而失效。

## 不在本次范围

- 自动生成整本数百章大纲。
- 大纲版本树和多人协作。
- 用大模型自动改写用户的大纲。
- 删除旧字段或一次性强制迁移所有项目。
