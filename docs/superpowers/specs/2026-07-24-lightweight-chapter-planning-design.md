# 轻量章节规划设计

## 目标

取消“导演”作为每章必跑的大模型 Agent，保留章节规划能力。生成流程应优先使用已经确认的总纲、阶段大纲、章节细纲和连续性状态，减少一次长提示词调用、重试和计划与正文互相冲突的机会。

## 方案

生成流程统一使用“章节规划”概念，不再把它表现为独立创作者。

1. 读取总纲、当前阶段、目标章节细纲、上一章结尾、相关角色卡、世界规则和当前账本。
2. 当目标章节有可执行细纲时，由本地规划器确定性生成章节合同，不调用规划模型。
3. 当目标章节没有细纲，或者细纲只有一句无法形成事件链时，才调用规划模型补齐章节合同。
4. 世界响应接收章节合同，只检查人物边界、信息可见性、规则和连续性，不改写剧情目标。
5. 写手只接收精简后的章节合同、场景执行信息、相关角色卡和事实状态。
6. 正文完成后，记忆阶段从实际正文提取章节摘要、事实、未完线索和账本变化。

## 章节合同

写手真正需要的规划产物只保留：

- 本章目标
- 主要阻力
- 四至六个有先后关系的事件节点
- 可见收获
- 实际代价
- 章末状态变化
- 下一章钩子
- 本章涉及的角色及其当场诉求

`chapter_summary`、最终 `ledger_updates`、正文已经发生的事实不属于规划产物，不能在正文之前生成。

## 回退条件

满足以下任一条件时才调用规划模型：

- 没有目标章节细纲。
- 细纲没有明确目标或事件结果。
- 细纲与上一章结束状态直接冲突，无法确定性修补。

规划模型只补缺失的章节合同字段，不重新生成世界观、角色卡、摘要或账本。

## 兼容与迁移

- 现有 `chapter_intent`、`event_plan` 和 `memory_constraints` 数据继续可读，避免历史章节失效。
- 新生成章节内部可以继续映射为旧字段，先保持 API 和页面兼容。
- 工作台将“导演规划”显示为“章节规划”，并明确显示来源是“已有大纲”还是“模型补全”。
- 配置中的旧 `director_model` 暂时作为规划模型兼容别名，待历史配置迁移完成后再删除。

## 失败处理

- 确定性规划缺少信息时进入模型补全，不直接终止正文生成。
- 模型补全失败时，页面显示“章节规划补全失败”和缺失字段，不再显示模糊的导演质量错误。
- 已有完整章节细纲时，规划模型故障不影响正文生成。

## 测试

- 有完整章节细纲时不调用规划模型，并能生成可用章节合同。
- 缺少章节细纲时只调用一次规划模型补全。
- 章节规划不提前产生摘要和最终账本更新。
- 世界响应不改变章节目标。
- 写手上下文包含精简章节合同，不包含完整导演 JSON。
- 历史章节和旧项目仍能正常打开、重写和继续生成。
