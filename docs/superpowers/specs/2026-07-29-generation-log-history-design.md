# 生成日志历史与改稿篇幅修复

## 目标

让生成日志页能够查看项目内过去的生成任务，并修复自动改稿因扩写超限而退回原稿的问题。

## 日志历史

- 后端新增文件项目生成任务列表接口，读取 `.story-system/generation-jobs/fgj-*.json`。
- 按 `updated_at` 倒序返回，默认最多 30 条，不把 `latest.json` 重复计入。
- 列表项只返回任务编号、章节、状态、进度、错误摘要和创建、更新时间；完整步骤仍通过已有单任务接口读取。
- 日志页首次加载历史列表，并默认选择最新任务。
- 当前任务处于排队或运行状态时，每 2 秒刷新当前任务；历史任务不轮询。
- 页面显示任务时间、目标章节和成功、失败状态，选择任务后展示该次完整写作流程与失败原因。

## 改稿篇幅

- 改稿硬上限按 `min(5500, max(4200, 原稿字数))` 计算。
- 原稿不足 4200 字时可以补到最低要求；原稿已经达标时不得越改越长；原稿超过 5500 字时必须压回项目上限。
- 提示词明确要求用替换、合并和删除完成修改，不得通过扩写整章解决审稿问题。
- 改稿调用的最大输出预算按硬上限动态收紧，并保留少量结构化输出余量，减少明显超长候选。
- 改稿安全报告和工作流日志增加原稿字数、候选字数，页面可以直接解释候选为何被拒绝。
- 仍保留现有安全门禁；超长候选不会覆盖原稿。

## 错误处理

- 项目没有历史任务时返回空列表，日志页显示“还没有生成记录”。
- 单个损坏的任务日志会被跳过，不影响其他记录。
- 历史列表加载失败时显示错误，但不影响项目其他页面。

## 验证

- API 测试覆盖历史排序、排除 `latest.json`、损坏日志跳过和空列表。
- 前端测试覆盖历史任务切换、默认选择最新任务和当前任务轮询。
- 提示词测试覆盖改稿硬上限公式，以及替换、合并、删除要求。
- 工作流测试覆盖日志中输出原稿与候选字数。
