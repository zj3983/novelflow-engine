# 工作区代码整理设计

## 目标

整理当前长期开发形成的混合工作区，使源码、测试、产品数据、运行数据和构建产物边界清楚，并将有效改动按职责提交。整理过程不改变现有写作行为，不重写小说正文，不删除 SQLite 数据和迁移备份。

## 当前情况

- 工作区同时包含写作流程、审稿简化、角色卡、Skill、题材拆分、项目页面等多批有效改动。
- `apps/api/data` 中包含正在使用的小说数据库和迁移备份，属于本地运行数据。
- `apps/web/.next-dev` 属于可重新生成的 Next.js 缓存。
- 后端、前端和测试改动互有关联，不能按修改时间随意拆开。

## 整理边界

### 必须保留

- `apps/api/data/stories.db`、WAL/SHM 文件和已有数据库备份。
- 所有小说项目、章节正文、角色卡和项目配置。
- 已通过测试的写作流程、题材插件、Skill、提示词页面和简化审稿功能。
- 有效设计文档、实现计划、迁移脚本和回归测试。

### 可以清理

- `apps/web/.next-dev` 等可以重新生成的构建缓存。
- Python 缓存、pytest 缓存、日志和本地临时输出。
- 由工具自动写入、但不应进入版本库的类型缓存或构建清单。

### 不在本轮处理

- 不大规模重写 `orchestrator.py` 或 `file_project_store.py`。
- 不改变提示词内容、生成流程、审稿门槛或页面交互。
- 不删除无法确认来源的源码、脚本、测试或文档。
- 不压缩、重写或清空 Git 历史。

## 忽略规则

补充 `.gitignore`，覆盖以下本地产物：

- `apps/api/data/backups/`
- `apps/api/data/**/*.db`
- `apps/web/.next-dev/`

现有数据库文件继续保留在磁盘，只是不进入 Git。删除缓存前先确认对应服务不依赖该目录；数据库目录绝不执行递归删除。

## 代码整理方式

1. 先检查未跟踪文件，按源码、测试、产品数据、文档、运行数据和缓存分类。
2. 检查修改文件中的自动生成内容、无用导入、重复类型判断和明显临时代码。
3. 只做可由现有测试证明等价的局部整理；涉及行为变化的重构留到单独任务。
4. 测试与对应实现放在同一提交，避免出现只有实现没有保护的中间状态。

## 提交分组

### 1. 后端写作工作流

包括 `packages/story_core`、`apps/api`、后端脚本、Skill 数据及对应 Python 测试。该提交覆盖写作包、剧情推演、角色卡、审稿、题材插件和项目迁移的完整后端状态。

### 2. 前端工作台

包括 `apps/web` 中的项目页、写作页、世界观、大纲、人物、提示词、Skill 和简化审稿界面，以及对应 API 类型。

### 3. 文档与工作区规则

包括 `.gitignore`、设计文档、实现计划和纯清理说明。运行数据库、备份、缓存和日志不进入提交。

如果文件依赖导致上述提交无法单独通过构建，则合并相邻提交，不使用危险的交互式拆补丁强行制造历史。

## 验证

- 后端整理后运行完整 `pytest`。
- 前端整理后运行 `npm run build`。
- 检查 `git diff --check` 和最终 `git status`。
- 重启 API 与页面服务，验证健康接口和真实项目页。
- 检查《我替宗门看守断香炉》的项目类型、章节数量、标题和正文哈希不变。

## 完成标准

- Git 状态只剩明确归类、准备提交的源码和文档。
- 本地数据库、迁移备份和小说正文完好。
- 运行缓存不再反复出现在 Git 状态中。
- 所有测试和前端构建通过。
- 提交信息能说明每组改动的职责，不混入运行数据。
