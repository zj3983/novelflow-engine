# 已有小说续写功能设计

## 目标

为 Novel Autogrowth Engine 增加“续写已有小说”项目创建方式。用户可以导入单个 TXT/Markdown 小说文件，或导入由多个 TXT/Markdown 章节组成的目录。系统完成章节解析、全书分析和续写起点确认后，将结果转为现有文件项目格式，继续复用大纲、写作、审稿、状态沉淀和章节管理能力。

默认流程为“先分析再确认”，同时提供“快速续写”。快速续写可以跳过人工确认，但不能跳过后台分析和审稿。

第一版不支持 EPUB、PDF、Word、网页抓取或在线书库导入。

## 用户流程

1. 用户在创建项目页面选择“续写已有小说”。
2. 用户选择单个 `.txt`/`.md` 文件，或选择一个章节目录。
3. 系统扫描来源，识别编码、章节边界和章节顺序，并生成导入预览。
4. 用户确认章节顺序、末章和解析警告。
5. 系统分批分析章节，生成故事概况、人物、世界观、力量体系、时间线、伏笔、文风和续写起点。
6. 用户确认或修正分析结果。
7. 用户设置续写方向、续写起点、章节数量、单章字数、忠实程度和禁写内容。
8. 系统可选生成后续大纲，然后生成下一章草稿。
9. 草稿通过连续性和质量检查后由用户确认，写入正式章节并更新项目状态。

## 创建入口

创建项目页面增加分段选择：

- `创作新小说`
- `续写已有小说`

选择续写后显示来源选择器。文件使用文件选择控件，目录使用现有本地目录浏览能力。两种来源进入同一个扫描和导入管线。

## 导入与解析

### 支持来源

- 单个 `.txt` 文件
- 单个 `.md` 文件
- 递归包含 `.txt`、`.md` 文件的目录

### 编码处理

按 BOM、UTF-8 严格解码和中文编码探测顺序识别文本编码。置信度不足或解码失败时停止导入，允许用户从常见编码列表中手动选择后重新扫描。原始字节不被修改。

### 章节识别

解析器按以下优先级建立章节：

1. 目录内的自然排序文件名。
2. 正文中的“第 X 章/节/回/卷”等标题。
3. Markdown 标题。
4. 无标题长文本的辅助分段。

辅助分段只产生待确认候选，不能未经确认直接进入分析。预览页支持改名、排序、合并和拆分章节。

### 导入校验

扫描报告至少包含：

- 来源路径和来源类型
- 检测编码
- 章节数量和总字数
- 首章、末章及其预览
- 空章、重复章、编号缺口和顺序异常
- 是否允许进入分析

对每个原始文件和标准章节计算内容指纹。重复导入同一来源时提示复用已有项目或创建副本。

### 文件布局

导入过程不修改用户源文件。项目目录保存只读副本和标准化结果：

```text
source/
  manifest.json
  original/
chapters/
  0001-title.md
.webnovel/
  import-report.json
  project.json
  state.json
.story-system/
  source-index.json
  analysis/
```

`source-index.json` 保存标准章节到原始文件、原始章节和字符范围的映射，供分析证据回溯使用。

## 分层分析

全书不能作为一个提示一次性发送。分析管线分为四层：

1. 章节层：摘要、人物状态、地点、事件、时间、物品、能力变化、未解决线索。
2. 分卷层：合并人物弧线、剧情线、力量体系、关系变化和伏笔。
3. 全书层：生成世界观、角色卡、关系网、时间线、力量体系和文风档案。
4. 续写起点层：重点分析续写点前最近 3 至 10 章，生成可执行的当前状态。

每条关键分析结果应保存来源章节和证据定位。无法从原文确认的推断必须标记置信度，不得直接成为不可变设定。

分析页面包含以下标签页：

- 故事概况
- 人物
- 世界观
- 力量体系
- 时间线
- 伏笔与未完剧情
- 文风
- 续写起点

用户可以修改分析结果。确认后，系统将结果转换成现有 `.webnovel` 和 `.story-system` 项目数据。

## 续写设置

续写设置包含：

- 续写起点，默认最新章
- 续写方向，可为空并由系统推断
- 预计续写章节数
- 单章目标字数
- `忠于原作` 或 `允许调整后续走向`
- 禁写内容和必须保留的事实
- 是否先生成后续 5 至 30 章大纲

原文中位于续写点之后的章节不得混入上下文。用户从中间章节建立分支时，项目必须记录分支起点，并将后续原文章节标记为参考外内容。

## 写作包与生成

续写写作包只携带当前章节需要的信息：

- 续写点前最近章节正文
- 当前人物、地点、物品、能力、任务和时间状态
- 未回收伏笔与未完剧情
- 原作叙事视角、句长、对话比例和描写密度
- 用户指定的续写方向
- 不得改变的事实
- 下一章目标、阻力、行动、回报和结尾钩子

文风档案只描述可执行特征，不保存用于复刻的长段原文，也不得要求模型复制原句。

生成结果先保存为草稿。只有草稿被接受后，才写入正式章节并更新人物、世界、时间线和伏笔状态。

## 快速续写

快速续写使用相同的数据管线，但自动采用以下默认值：

- 从最新章继续
- 忠于原作
- 自动推断下一章方向
- 使用项目默认字数
- 自动生成一章
- 自动运行一次审稿和最多一次修订

存在阻断问题时，快速续写必须停止并展示问题，不能绕过章节缺失、续写点不明确或连续性冲突。

## 后端边界

新增独立的导入会话，避免未确认内容污染项目：

```text
POST /continuation-imports/scan
POST /continuation-imports
GET  /continuation-imports/{id}
PUT  /continuation-imports/{id}/chapters
POST /continuation-imports/{id}/analyze
GET  /continuation-imports/{id}/analysis
PUT  /continuation-imports/{id}/analysis
POST /continuation-imports/{id}/create-project
```

扫描接口处理文件或目录来源；导入会话保存标准章节和进度；`create-project` 是唯一把确认结果转换成正式文件项目的操作。项目创建后，继续使用现有文件项目写作和生成接口。

耗时分析通过后台任务执行。任务状态至少包括 `queued`、`parsing`、`analyzing`、`ready`、`failed` 和 `cancelled`，并记录已完成的章节范围，使失败后可以断点重试。

## 前端组成

- 创建方式分段选择器
- 文件/目录来源选择器
- 扫描报告与章节预览编辑器
- 分析进度页
- 分析结果标签页
- 续写设置表单
- 快速续写命令
- 草稿质量与连续性报告

长任务必须显示当前阶段、已处理章节数和错误信息。固定格式的章节列表和进度区域使用稳定尺寸，避免任务状态更新时页面跳动。

## 异常处理

- 编码不确定：要求手动选择编码后重试。
- 无法识别章节：进入辅助分段预览，禁止直接分析。
- 空章、重复章、编号缺口：定位到具体文件和章节。
- 中途失败：保留已完成分析，从失败批次继续。
- 分析冲突：标记待确认，不写入正式设定。
- 草稿失败：保留失败草稿和报告，不推进正式状态。
- 源文件变化：比较指纹并要求重新扫描，不静默混合新旧原文。

## 测试与验收

### 单元测试

- UTF-8、UTF-8 BOM、GBK 编码识别
- TXT 标题和 Markdown 标题识别
- 中文数字、阿拉伯数字章节排序
- 目录递归、重复文件、空文件和缺章检测
- 章节合并、拆分、改名和排序
- 内容指纹与重复导入检测
- 分层分析合并和证据来源保存
- 从中间章节续写时排除未来原文
- 草稿接受前不更新正式状态

### API 测试

- 导入会话完整生命周期
- 后台分析状态和失败重试
- 未确认章节不能创建项目
- 分析冲突未处理时不能快速续写
- 创建后的项目符合现有文件项目格式

### 浏览器测试

- 单 TXT 导入到生成下一章的完整流程
- 章节目录导入到生成下一章的完整流程
- 手动选择编码并重新扫描
- 调整章节顺序、合并和拆分
- 分析结果确认与修改
- 快速续写成功和阻断失败状态

## 完成标准

- 用户可以从单个 TXT/Markdown 或章节目录创建续写项目。
- 导入前能够确认章节顺序和续写起点。
- 人物、世界观、时间线、力量体系、伏笔和文风分析可追溯到原文章节。
- 创建后的项目可以使用现有大纲、写作、审稿和继续生成流程。
- 生成草稿不会在接受前污染正式项目状态。
- 导入和分析失败可以定位、重试并恢复。
