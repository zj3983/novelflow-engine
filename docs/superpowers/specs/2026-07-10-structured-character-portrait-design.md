# 结构化人物侧写设计

## 目标

为每个正式出场人物建立可编辑的完整角色卡。角色卡由系统规则生成基础模板，用户维护主档，写作模型只能读取本章需要的表现切片，不能自行改写人物主档。

## 当前问题

现有角色模型已经保存动机、行为逻辑、说话方式、心理维度和表演信息，但默认值不完整，页面只展示少数字段，正文提示词又把人物压缩为动机、说话和风险三项。结果是角色卡看起来存在，模型实际拿不到足够具体的性格依据。

## 数据结构

在现有 `CharacterState` 上增加结构化 `personality_portrait`，不新增另一套人物主档。侧写分为八组：

1. `temperament`：外在印象、核心性格、内在矛盾、价值观、底线。
2. `psychology`：核心欲望、主要恐惧、盲点、防御方式、羞耻点。
3. `behavior`：日常模式、压力模式、冲突反应、失败反应、决策倾向。
4. `emotion`：情绪触发点、克制方式、失控表现、常见小动作。
5. `social`：面对陌生人、朋友、上位者和敌人的不同状态。
6. `voice`：常用词、句子习惯、回避话题、撒谎方式、生气和放松时的语言变化。
7. `growth`：初始缺陷、稳定不变量、变化条件、阶段方向。
8. `writing_limits`：不能出现的行为、语言和关系越界。

关系侧写继续使用现有 `relationships`，但每段重要关系补充需求、误解、表面态度和真实态度。

## 基础模板生成

基础侧写由本地规则生成，不调用大模型。规则根据角色类型、剧情职责、身份、题材和已有字段组合模板：

- 主角模板更完整，强调欲望、恐惧、矛盾、压力反应和成长弧线。
- 长期配角保留完整行为、关系和声音信息。
- 服务型 NPC 重点刻画利益、岗位边界、待人差异和可重复识别的小习惯。
- 候选新人物在出场前生成侧写；未确认人物保持 `proposed`，不能作为已出场事实。

已有用户内容优先。规则模板只补空字段，不覆盖用户已填写的内容。

## 写作提取

完整角色卡不直接进入正文提示词。系统根据本章计划选择出场人物，并为每人生成一个 300 至 500 字的本场表现切片，只包含：

- 本章目标和当前情绪。
- 当前压力下的行为模式。
- 与场内其他人物的关系态度。
- 本场对话和动作特征。
- 本章可能触发的性格矛盾。
- 必须避免的人设越界。

主角和主要对手优先；普通 NPC 只提取与当前岗位和交互有关的部分。人物未出场时不注入提示词。

## 页面与保存

角色卡页面按“身份、性格、心理、行为、情绪、社交、语言、成长、关系、写作禁区”分区展示。所有侧写字段可以编辑并保存。

保存动作只更新项目人物主档，不触发章节生成，不调用大模型。空字段可以执行“补全基础模板”，该操作仍使用本地规则，并在写入前保留已有内容。

## 兼容与迁移

旧项目加载时按需补齐 `personality_portrait` 默认结构，不强制重写项目文件。首次保存角色卡时再持久化完整结构。现有 `core_motivation`、`behavior_logic`、`performance_profile` 和三维侧写继续保留，并作为模板生成输入，避免破坏已有项目。

## 验证

- 单元测试覆盖主角、长期配角、服务 NPC 和旧项目迁移。
- 测试用户填写内容不会被模板覆盖。
- 测试本章只提取计划出场人物，且提示词不包含全量角色库。
- API 测试覆盖读取、编辑、补全和非法角色名。
- 页面构建测试和本地浏览器检查覆盖展开、编辑、保存和移动端显示。
