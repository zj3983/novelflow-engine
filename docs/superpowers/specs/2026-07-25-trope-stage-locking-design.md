# 小说套路自动选择与阶段锁定设计

## 目标

让现有 `trope_templates` 从类型配置数据真正进入开篇、大纲、章节写作和审稿流程，同时避免模型在每章重新挑选套路造成剧情漂移。

系统自动完成三层决策：全书选择主套路、每个故事阶段锁定阶段套路、仅在关键章节推进一个明确的套路节点。用户不需要逐章配置，已有项目和没有模板的小说类型仍可沿用原流程。

## 范围

第一版包含：

- 把当前小说类型模板与通用模板作为自动选择候选。
- 在开篇方向中选择一个主套路，并随选中的方向进入全书大纲。
- 为每个分卷或故事阶段锁定一个阶段套路。
- 在章节计划中按需安排一个可选套路节点。
- 将当前阶段套路和当前章节节点注入章节写作提示词。
- 在审稿中检查已安排节点是否兑现，以及模板的避免事项是否被违反。
- 对旧项目、未知模板和模板库调整提供兼容降级。

第一版不包含：

- 让用户逐章手动挑选套路。
- 每章强制安排打脸、反转或爽点。
- 根据已经写出的正文自动重排后续整卷套路。
- 为套路建立单独的 Agent、独立模型配置或额外模型调用。
- 复制整套模板到每个项目文件中。
- 新增重生创业、末世等小说类型或扩充模板内容；这些可在调度链路稳定后单独进行。

## 核心原则

### 阶段锁定

全书主套路表达长期读者承诺，阶段套路表达当前分卷的主要兑现方式。主套路一经开篇方向确认即保持稳定；阶段套路一经大纲生成即在该阶段内保持稳定。章节生成不得重新选择或替换阶段套路。

### 关键节点推进

并非每章都要执行套路。大纲规划器只在需要建立、升级、反转或兑现阶段套路的章节填写 `trope_beat`。普通承接章节保持该阶段的背景约束，但不被强制制造重复爽点。

### 引用而非复制

项目大纲只保存稳定的模板 ID 和当前节点，不保存模板全文。运行时根据小说类型解析模板内容，从而让模板维护仍集中在类型目录中。

## 数据结构

### 开篇方向

`OpeningDirection` 增加：

```text
primary_trope_id: str
```

每个候选开篇方向必须从当次提供的候选 ID 中选择一个主套路。不同方向可以选择不同套路，以便三个方向不仅换措辞，也体现不同的成长和冲突机制。

### 全书大纲

`OverallOutline` 增加：

```text
primary_trope_id: str | None = None
```

选择开篇方向并生成大纲时，将该方向的 `primary_trope_id` 带入全书大纲。直接生成大纲时，由大纲规划器自动选择。字段可空以兼容旧项目。

### 阶段大纲

`ArcOutline` 增加：

```text
trope_id: str | None = None
```

每个阶段只锁定一个主要套路。它可以与全书主套路相同，也可以选择兼容的辅助套路，但必须服务于该阶段目标、障碍和回报。

### 章节计划

`ChapterPlan` 增加：

```text
trope_beat: str | None = None
```

`trope_beat` 保存当前阶段模板 `beats` 中的一个原始节点文本。为空代表本章不主动推进套路。第一版不增加完成状态；章节计划是预期状态，实际完成情况由审稿结果判断。

## 候选模板解析

新增一个聚合边界，负责根据小说类型返回稳定、去重、可供提示词和运行时共同使用的套路候选：

1. 读取当前类型插件的 `trope_templates`。
2. 合并通用模板。
3. 按模板 ID 去重；类型专用模板优先于同 ID 的通用模板。
4. 输出 ID、名称、触发条件、推进节点、回报和避免事项。

自动选择只允许引用候选列表中的 ID。通用模板和类型模板合计全部提供，不额外调用模型做预筛选；当前模板数量足够小，保留完整候选能避免规则分散。

`novel_type_prompt_context()` 增加精简的候选模板区块，使开篇方向和大纲规划器都使用同一个来源。章节写作不接收完整候选库，只接收已经锁定的单个模板。

## 自动选择规则

### 开篇主套路

开篇方向生成器根据标题、创意、小说类型承诺和候选模板，选择最能支撑长期成长线的模板。输出必须包含候选中的 `primary_trope_id`。结构校验拒绝未知 ID，并沿用现有重试或生成失败处理。

### 阶段套路

大纲规划器为每个阶段选择一个 `trope_id`，选择依据依次为：

1. 与阶段目标和回报直接相关。
2. 与全书主套路兼容。
3. 相邻阶段尽量不要无意义重复同一套完整节拍。
4. 不得违反小说类型的规则和禁用冲突模式。

阶段可以继续使用主套路，也可以用辅助套路完成局部变化。系统不设固定轮换算法，避免把故事结构变成机械配方；合法性由 ID 校验保证，适配性由规划提示词和语义校验保证。

### 章节节点

大纲规划器可从阶段模板的 `beats` 中为关键章节选择一个 `trope_beat`。同一节点可以跨数章展开，但只有负责发生实质推进的章节需要标记。规划时遵守：

- 阶段前部优先建立触发条件和限制。
- 阶段中部优先升级代价、阻力或能力运用。
- 阶段后部优先兑现回报并制造下一阶段钩子。
- 不要求每个节点全部出现，也不要求每章有节点。
- `trope_beat` 必须属于当前阶段模板；否则视为大纲语义错误。

## 运行时数据流

```text
小说类型插件 + 通用模板
        ↓
套路候选聚合器
        ↓
开篇方向选择 primary_trope_id
        ↓
全书大纲保存主套路
        ↓
阶段大纲锁定 trope_id，并给关键章节安排 trope_beat
        ↓
章节种子解析当前阶段模板
        ↓
写作提示词接收单个 trope_contract
        ↓
审稿检查当前节点和避免事项
```

章节种子新增精简的 `trope_contract`，包含：

```text
template_id
name
trigger
current_beat
payoff
avoid
```

`current_beat` 可以为空。写作提示词只接收该契约，不接收所有模板，减少上下文长度并阻止写作模型自行换套路。

## 写作与审稿行为

写作模型将阶段套路视为结构约束，而不是必须照抄的情节。存在 `current_beat` 时，本章必须产生可观察的推进；不存在时，只需保持阶段承诺、回报方向和避免事项，不得凭空启动另一个套路。

审稿增加两类确定性上下文：

- 节点兑现：仅当 `current_beat` 非空时检查本章是否发生了对应推进。
- 套路禁忌：检查模板 `avoid` 中的机械重复、无代价升级或其他具体风险。

审稿结论沿用现有问题与修订流程，不增加新的 Agent。模板约束进入现有写作和审稿提示词，也不产生额外模型调用。

## 兼容与错误处理

- 旧项目缺少三个新字段时，按 `None` 读取并继续原流程。
- 小说类型没有模板时，不生成套路选择，章节种子不包含 `trope_contract`。
- 保存的模板 ID 在当前目录中不存在时，记录可诊断警告并忽略该契约，不阻塞旧章节读取。
- 新生成的开篇或大纲引用未知 ID 时，视为模型结构或语义错误，走现有重试和失败路径，不静默换成其他模板。
- `trope_beat` 不属于当前阶段模板时，新生成大纲校验失败；读取旧数据时降级忽略该节点。
- 单独生成大纲和从开篇方向生成大纲必须走同一候选解析与校验路径。

## 页面影响

第一版不增加独立套路配置页面，也不增加逐章操作控件。现有小说类型页面继续负责展示模板库；项目大纲页面可以随现有大纲数据展示主套路、阶段套路和关键章节节点，但展示不是写作链路生效的前置条件。

CLI 和 API 模型配置不受影响。套路选择由现有开篇或大纲生成调用一并完成，因此不需要全局或各 Agent 的额外配置。

## 测试

### 模型与解析

- 新字段可序列化、反序列化，旧数据缺字段仍可读取。
- 类型专用与通用模板正确合并、去重。
- 未知模板 ID 和非法 `trope_beat` 在新生成结果中被拒绝。
- 已删除模板在旧项目运行时降级而不崩溃。

### 开篇与大纲

- 开篇提示词包含精简候选，生成结果包含合法 `primary_trope_id`。
- 从选中方向生成大纲时保留主套路。
- 单独生成大纲时能够自动选择主套路。
- 每个阶段只生成一个合法 `trope_id`。
- 仅关键章节包含合法 `trope_beat`，普通章节允许为空。

### 章节生成

- 章节种子只解析当前阶段锁定的模板。
- 写作提示词只包含一个精简 `trope_contract`，不包含完整候选库。
- 没有当前节点时不会强制本章完成套路节点。
- 存在当前节点时写作与审稿提示词均包含该节点。
- 该功能不增加 provider 调用次数。

### 回归

- 没有套路模板的类型仍可生成开篇、大纲和章节。
- 旧项目可以继续生成下一章。
- 现有小说类型规则、世界模拟、连续性和章节治理信息仍正常进入写作链路。
- API 与 CLI provider 使用同一套套路调度结果。

## 验收标准

- 现有模板不再只存在于配置和模拟蓝图中，而是能追踪到实际写作提示词。
- 全书有一个稳定主套路，每个阶段有且只有一个锁定套路。
- 阶段内章节不会自行改选套路。
- 只有关键章节推进明确节点，普通章节不会被强制重复爽点。
- 模板的回报和避免事项进入现有写作与审稿流程。
- 单独生成大纲与开篇后生成大纲行为一致。
- 旧项目和无模板类型保持兼容，且不增加额外模型调用。
