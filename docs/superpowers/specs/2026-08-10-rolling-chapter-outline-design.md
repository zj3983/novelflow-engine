# 滚动细纲补全设计

## 目标

当目标章节没有细纲时，系统必须先补全细纲，再进入正文生成。固定的“压力选择线、关系摩擦线、规则兑现线”不再代替细纲，也不再要求用户每章手动选择。

## 适用范围

- 新章节生成：缺少目标章细纲时触发滚动补全。
- 已有细纲的新章节：直接进入正文生成。
- 旧章重写：使用该章已有细纲和该章之前的历史状态，不自动生成未来细纲。
- 本次只调整规划与写作衔接，不新增 Agent，不修改正文审稿流程。

## 流程

1. 用户点击“生成下一章”。
2. 后端检查目标章节是否存在可用细纲。
3. 如果不存在，调用现有大纲规划能力，一次生成从目标章开始的5章滚动细纲。
4. 将生成结果写入项目大纲，并记录本次补全范围和来源。
5. 重新构建写作包，确认目标章细纲已经存在。
6. 正文流程读取目标章细纲后继续执行。
7. 剩余可用细纲少于2章时，在下一次生成前再补5章，但不得覆盖已经写过或人工修改的细纲。

## 细纲结构

每章至少包含：

- 章节编号与暂定标题
- 本章目标
- 核心冲突
- 出场人物及其本章作用
- 2至4个主要场面
- 可见推进或收益
- 必须付出的代价
- 本章处理或推进的伏笔
- 章末钩子
- 预期状态变化

细纲必须从当前卷纲、最近三章摘要、当前人物状态、关系图谱、开放伏笔和世界规则中取得依据。不得把远期规划写成已经发生的事实。

## 页面表现

- 删除写作页固定的三张“下一章方向”卡。
- 有细纲时显示简短的“本章细纲”摘要。
- 没有细纲、正在补全时显示“正在补全第X至Y章细纲”。
- 补全失败时正文生成停止，保留明确错误和重试入口，不能静默退回抽象方向模板。
- 后续可以在大纲页编辑生成的细纲；人工修改后标记为人工版本，滚动补全不得覆盖。

## 数据边界

- 总纲负责长期目标与卷级阶段。
- 滚动细纲负责未来5章的可执行剧情安排。
- 导演只把当前章细纲转成场景执行计划，不重新决定故事方向。
- 写手只根据当前章细纲、导演计划和相关上下文写正文。
- 审稿不参与生成细纲，只检查正文事实和连续性。

## 失败处理

- 细纲返回缺字段、章节号错位或越过当前卷范围时，拒绝保存。
- 部分章节生成成功、部分失败时不写入，避免留下半批数据。
- 保存采用原子更新，并保留旧大纲备份。
- 正文生成前再次检查目标章细纲，避免并发情况下使用空细纲。

## 验收标准

- 第148章缺少细纲时，系统先生成第148至152章细纲，再生成第148章正文。
- 第149至152章生成时不再要求选择抽象方向。
- 第153章生成前自动补下一批滚动细纲。
- 页面不再显示固定的三类方向卡。
- 已存在或人工修改的细纲不会被覆盖。
- 旧章重写不读取未来细纲。
- CLI和API模式走同一套流程。
