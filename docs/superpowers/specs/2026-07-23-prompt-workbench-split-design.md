# 提示词工作台拆分设计

## 目标

把当前混合展示的提示词页面拆成三个职责明确的视图：原始模板、动态上下文和真实调用记录。用户能够看清系统固定要求、某章读取了什么，以及模型当时实际收到了什么。

## 页面结构

项目导航仍保留一个“提示词”入口，页面内部使用三个标签：

1. **提示词模板**：只展示固定指令和变量占位符，不注入当前小说正文、大纲、角色卡或世界状态。
2. **上下文模块**：展示目标章节可读取的项目数据，包括核心事实、大纲约束、剧情计划、出场角色卡、题材写法和表达模块。
3. **实际调用**：按章节、阶段和尝试次数展示生成时保存的调用快照。

默认进入“提示词模板”。URL 使用 `?view=templates|context|calls` 保存当前视图，章节仍使用 `chapter` 参数选择。

## 模板分层

模板采用“全局默认 + 项目覆盖”：

- 全局模板是所有项目的默认来源，按 `director`、`writer`、`revision`、`expansion`、`compression` 分开保存。
- 项目可以只覆盖某一个模板；没有覆盖的模板继续继承全局版本。
- 页面明确显示当前来源是“全局默认”还是“项目覆盖”。
- 项目覆盖可以编辑、保存和恢复全局默认。恢复操作只删除该项目的覆盖，不修改全局模板。
- 第一版只提供文本编辑和受支持变量列表，不提供条件表达式或可编程模板语法。

全局模板由独立的模板仓储负责，项目覆盖由 `FileProjectStore` 负责。模板解析只接受登记过的变量，缺失必需变量时拒绝保存并返回具体变量名。

## 上下文模块

上下文页只读，不承担源数据编辑：

- 每个模块显示名称、职责、来源、使用阶段、字符数和内容。
- 提供跳转到大纲、角色卡、世界观等源页面的入口。
- 当前不存在但被阶段声明依赖的模块显示“本次未提供”，不能静默消失。
- Skill 模块暂不参与本次拆分，保持禁用状态；页面只展示实际启用并实际注入的模块。

上下文接口返回结构化模块，不返回组装后的完整 Prompt。

## 实际调用记录

每次模型调用都保存不可变快照，包括成功、失败和重试：

- `call_id`、项目、章节、阶段、尝试序号和时间。
- 提供方、模型、温度和调用耗时。
- 系统指令、最终用户 Prompt、引用模块键及模块内容摘要。
- 调用状态、错误信息、输出字符数和输出摘要。
- 模板来源及模板版本摘要，用于判断调用使用了全局模板还是项目覆盖。

调用记录在发起模型请求前先写入 `started`，完成后原子更新为 `succeeded` 或 `failed`。记录只读，不允许页面修改。项目内按 JSONL 索引和独立 JSON 详情保存，避免一个长篇项目把单个文件撑得过大。

旧章节没有真实调用快照时，只能显示“推算预览”。推算预览必须带 `reconstructed: true` 和醒目标识，不得进入“实际调用”列表冒充历史记录。

## 数据流

1. 生成阶段选择全局模板。
2. 若项目存在对应覆盖，则使用项目覆盖。
3. 按阶段依赖选择上下文模块。
4. 渲染最终系统指令和用户 Prompt。
5. 创建 `started` 调用快照。
6. 调用模型。
7. 将同一快照更新为成功或失败，并保存输出摘要或错误。
8. 页面从调用记录接口读取真实历史；当前状态重建接口只服务“推算预览”。

## 接口边界

- `GET /prompt-templates`：读取全局模板列表。
- `PUT /prompt-templates/{template_key}`：修改全局模板。
- `GET /file-projects/{project_id}/prompt-templates`：读取解析后的项目模板及来源。
- `PUT /file-projects/{project_id}/prompt-templates/{template_key}`：保存项目覆盖。
- `DELETE /file-projects/{project_id}/prompt-templates/{template_key}`：恢复全局默认。
- `GET /file-projects/{project_id}/prompt-context?chapter_number=N`：读取结构化上下文模块。
- `GET /file-projects/{project_id}/prompt-calls?chapter_number=N`：读取调用记录摘要。
- `GET /file-projects/{project_id}/prompt-calls/{call_id}`：读取单次调用完整快照。
- `GET /file-projects/{project_id}/prompt-preview?chapter_number=N`：保留为推算预览兼容接口，并明确返回 `reconstructed: true`。

## 错误处理

- 模板变量不合法时返回 `422`，并列出未知变量或缺失变量。
- 项目覆盖写入失败时保留旧版本，不产生半写文件。
- 调用快照写入失败时不发起模型请求，避免出现无法追踪的调用。
- 模型调用异常时仍保存失败记录，页面显示错误摘要，不显示永久加载状态。
- 调用详情不存在时返回 `404`，列表加载失败不影响模板和上下文页面。

## 验收与测试

- 模板页不包含当前正文、角色卡实例或大纲实例。
- 项目覆盖只影响当前项目，删除覆盖后立即恢复全局模板。
- 上下文接口与对应生成阶段实际读取的模块键一致。
- 每次成功、失败和重试均生成独立调用记录。
- 实际调用详情中的最终 Prompt 与发送给提供方的字符串完全一致。
- 旧的重建预览明确标注为推算内容，不出现在真实调用列表。
- 三个页面分别处理加载和错误状态，不因一个接口失败让整个提示词工作台卡住。
- 后端单元/API 测试、前端 Playwright 测试和生产构建全部通过。

## 非目标

- 本次不启用或重构 Skills。
- 本次不制作复杂的可视化 Prompt 编排器。
- 本次不修改小说大纲、角色卡和世界观的数据结构。
- 本次不把历史重建 Prompt 伪造为真实调用快照。
