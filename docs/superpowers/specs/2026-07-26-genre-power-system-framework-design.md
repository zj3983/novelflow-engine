# 分类型结构化力量体系设计

## 目标

为所有小说类型建立具体、可执行、可持续引用的超凡力量体系。系统不再只生成几条笼统的等级描述，而是由小说类型提供结构骨架，再结合项目创意生成独有的职业、境界、能力、资源、代价和克制规则。

本次同时补全 `p-gou-webgame-restored` 的六职业体系，并让后续创建的所有类型项目自动获得完整力量体系。

## 核心原则

1. 所有内置小说类型都允许并要求生成超凡力量体系，包括都市、言情和悬疑。
2. 小说类型只规定体系必须回答的问题，不固定项目中的专有名词和具体设定。
3. 力量增长必须同时描述获得条件、可见效果、资源消耗、失败代价和能力边界。
4. 职业、境界、技能和装备必须形成闭环，不能各自成为互不关联的设定清单。
5. 大纲与章节写作必须读取同一份力量体系和成长账本，禁止临场发明冲突规则。
6. 旧项目继续兼容现有 `world_blueprint.power_system` 列表，并可逐步升级到结构化体系。

## 方案选择

采用“类型骨架 + 项目生成 + 完整性校验 + 写作持续引用”的结构化方案。

不采用纯提示词方案，因为提示词无法稳定保证字段完整。不采用每个类型固定一套体系，因为会导致同类型项目重复，且无法体现项目自身创意。

## 数据结构

### 类型层：`power_system_template`

在小说类型记录中增加可编辑的力量体系骨架。骨架描述该类型必须生成的内容、建议形态和质量要求，不保存某一本小说的具体设定。

核心字段：

- `system_form`：职业、境界、血脉、契约、规则权限等推荐形态。
- `required_sections`：该类型必须具备的体系章节。
- `progression_shape`：成长阶段数量、关键晋升点及其叙事作用。
- `branching_rules`：职业或能力分支的最低复杂度。
- `resource_rules`：力量获得和使用依赖的资源类型。
- `cost_rules`：失败、透支、污染、暴露或因果代价。
- `conflict_rules`：同级、越级、克制和团队配合的边界。
- `ledger_fields`：写作过程中必须持续记录的状态。
- `quality_checks`：判定体系是否具体、闭环和可写的检查项。

自定义小说类型也可以编辑这份骨架；未填写时继承通用网文骨架。

### 项目层：`power_system_spec`

项目生成结果保存在 `world_blueprint.power_system_spec`，包含：

- `name`：体系名称。
- `origin`：力量来源、传播方式和觉醒条件。
- `attributes`：基础属性及每项属性的实际作用。
- `paths`：职业、流派、血脉或能力路线。
- `stages`：完整等级、境界和晋升节点。
- `skills`：技能类别、获得方式、升级与组合规则。
- `equipment`：武器、防具、法宝、媒介或异常道具规则。
- `resources`：经验、灵气、材料、精神力等资源循环。
- `advancement`：晋升条件、任务、仪式、试炼和失败结果。
- `costs`：使用力量和越级行动的消耗及永久风险。
- `counters`：克制关系、队伍定位与反制手段。
- `boundaries`：同级胜负、越级上限和不可突破的硬边界。
- `social_impact`：力量对组织、法律、经济和日常生活的影响。
- `visibility`：角色如何判断他人强弱，哪些信息不可直接获知。
- `continuity_ledger`：等级、技能、装备、资源、负面状态等持续状态。

现有 `world_blueprint.power_system: list[str]` 保留为兼容摘要，由结构化体系派生；读取旧项目时，如果只有列表，不伪造缺失内容，但会将项目标记为需要补全。

## 分类型骨架

### 网游

必须生成基础属性、职业树、等级阶段、技能、装备、转职任务、队伍定位、职业克制、死亡惩罚和状态面板规则。职业不能只有名字，必须说明核心资源、适用武器、战斗循环、优势、弱点和进阶路线。

### 玄幻

必须生成力量来源、血脉或体质、境界、战技、资源、异物、领域或法则，以及跨境战斗边界。机缘必须伴随炼化条件和风险。

### 仙侠

必须生成灵根、功法、术法、法宝、境界、传承、渡劫与因果代价。修炼速度、寿元和资源稀缺性必须互相约束。

### 都市

必须生成异能或隐秘职业、觉醒等级、使用代价、现实身份掩护、管理机构和暴露风险。超凡力量不能消除法律、舆论和社会资源的约束。

### 言情

必须生成超凡血脉、契约、共鸣或命运能力，说明能力如何受关系变化影响。情感选择可以改变能力条件，但不能被数值替代，也不能用超凡规则强行证明爱情。

### 悬疑

必须生成灵视、通灵、记忆读取或其他调查能力，并为每项能力规定证据效力、误判条件、使用代价和不可知范围。超凡能力只能提供线索，不能直接替代推理闭环。

### 规则怪谈

必须生成规则权限、污染阶段、认知抗性、异常道具、违规代价与存活条件。真假规则必须可以通过行动验证，且不存在无条件免疫。

### 通用网文

根据项目 premise 选择最合适的超凡形态，但必须生成项目层全部核心章节。类型不明确时，优先建立少而清晰的路线，不堆叠多个互不相干的体系。

## 生成流程

1. 创建项目或补全世界设定时，读取当前小说类型的 `power_system_template`。
2. 将项目 premise、角色定位、长篇规划和类型骨架共同交给世界生成阶段。
3. AI 返回结构化 `power_system_spec`，同时生成简短兼容摘要。
4. 校验器检查章节完整性、分支数量、阶段连续性、代价、克制和边界。
5. 不完整结果沿用现有生成重试机制；达到重试上限时明确报告缺失章节，不保存成“已完成”力量体系。
6. 保存后同步生成 `设定集/力量体系.md`，供作者查看和编辑。
7. 大纲、章节计划、写作、审稿和连续性更新按需读取结构化切片，避免一次塞入整份设定。

## 当前网游项目迁移

`p-gou-webgame-restored` 使用六个基础职业：战士、法师、游侠、盗贼、牧师、召唤师。

统一成长节点：

- Lv.1-9：见习者阶段，通过初始武器和通用技能确认倾向。
- Lv.10：完成职业任务，获得正式基础职业。
- Lv.20：专精节点，只强化战斗方向，不视为再次转职。
- Lv.30：进入进阶职业分支。
- Lv.60：获得传承职业或高阶权柄。

主角路线锁定为“见习者 -> 元素法师 -> 元素宗师”，女主的游侠路线和现有战士、盗贼角色同步落入统一职业树。清理大纲中把 Lv.20 写成第二次转职的冲突，但不改动已经发生的正文事实。

每个基础职业至少生成两条 Lv.30 分支，并包含核心属性、职业资源、武器护甲、技能类别、战斗循环、优势、弱点、转职任务和队伍职责。

## 展示与编辑

项目世界页继续显示“力量体系”，但改为按来源、阶段、路线、技能、资源、代价、克制和社会影响分节展示。保留 Markdown 镜像作为可读设定集，不要求用户直接编辑 JSON。

小说类型库增加力量体系骨架编辑区域。内置类型提供默认骨架，自定义类型可覆盖；恢复内置默认值时一并恢复其骨架。

## 校验规则

生成结果至少满足：

- 有明确力量来源和获得方式。
- 有不少于三个连续成长阶段。
- 每个阶段都有进入条件、能力变化和失败代价。
- 至少存在两条可区分路线，或明确说明单路线体系的合理性。
- 技能、装备和资源能映射到具体路线与阶段。
- 存在可执行的克制关系和越级边界。
- 说明强者为什么不能无限解决低阶冲突。
- 账本字段足以记录角色当前可用力量。
- 禁止只用“综合实力提升”“领悟更深”等模糊句子代替规则。

网游类型额外要求六个基础职业齐全，每个职业至少两个进阶方向，并确保 Lv.10、Lv.20、Lv.30、Lv.60 的含义不冲突。

## 兼容与失败处理

- 不删除旧 `power_system` 字段，不覆盖用户手写的非托管 Markdown。
- 结构化字段缺失时，现有项目仍可打开和写作，但页面提示需要补全。
- 从结构化体系生成摘要是单向派生，不从摘要反推并保存虚构细节。
- 类型切换后保留原体系作为待确认内容，不能静默套用不匹配的新骨架。
- AI 返回格式错误或字段缺失时，不落盘半成品。

## 测试范围

- 八个内置类型均能提供有效力量体系骨架。
- 自定义类型可保存、读取、覆盖和恢复骨架。
- 新建项目能生成并校验结构化力量体系。
- 缺少阶段、代价、克制或边界的结果校验失败。
- 旧项目只含列表时可以正常读取并显示待补全状态。
- 结构化体系能够稳定渲染为 Markdown，且不覆盖手写文件。
- 大纲和章节提示只读取与当前阶段相关的体系内容。
- 当前网游项目六职业、四个成长节点和主角路线保持一致。
- Lv.20 不再被写成第二次转职。
