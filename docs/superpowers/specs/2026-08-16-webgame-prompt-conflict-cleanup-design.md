# 网游提示词冲突清理设计

## 目标

让网游题材模板只提供可复用的机制边界，不再覆盖项目事实、章节细纲或角色当前状态；模块化写手和旧写作包都不能把某一本旧书的职业、怪物、道具或人物带进新项目。

## 规则优先级

生成时采用固定顺序：已确认事实与世界规则、章节细纲、活动角色与实体卡、导演场景计划、题材模板、通用写法。低层模块只能补充表达方法，不能改写高层已经确定的事实。

## 模块边界

- 导演：把细纲变成可执行场景，不允许题材默认值覆盖细纲。
- 写手：只接收当前场景需要的角色状态与写法规则。首次能力如何出现服从细纲和角色认知，不统一强制为被动触发。
- 网游题材模板：保留等级、任务、交易、身份分层、信息可见性等机制规则；删除固定人物、职业、武器、怪物、材料和现实困境。
- 旧写作包：继续兼容页面和手工写作，但默认场景与硬锁改为中性内容，具体值从项目状态读取。

## 角色上下文

写手只看到当前身份、位置、伤势、资源、即时目标和必要的现实/游戏状态。角色来历、长期故事驱动和作者后台措辞不再整块序列化进写手提示词。

## 验收

- 导演提示词明确项目事实和细纲优先。
- 通用写手不包含“被动触发、误打误撞”以及玄幻专用动作词。
- 角色提示词不泄漏 `origin`、`hidden_matters`、`游戏背景设定`、`背景数据` 等后台信息。
- 一个全新网游项目的写作包不出现夜烬、法杖、火球术、灰狼毒腺或粗糙狼皮。
- 现有模块化导演、写手和写作包测试通过。
