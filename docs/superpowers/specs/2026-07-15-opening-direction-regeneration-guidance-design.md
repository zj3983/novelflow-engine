# 开篇方向重新生成补充要求设计

## 目标

允许用户在重新生成三个开篇方向时填写一次性补充要求。补充要求只影响当前这次生成，不写入开书简报、作者约束、总纲或其他项目状态。

## 交互

- 首次生成保持现状，不显示补充要求输入框。
- 已有候选方向或上次生成失败时，在“重新生成”操作附近显示“本次补充要求”多行输入框。
- 输入可留空，去除首尾空白后最多 1000 字。
- 重新生成期间输入框和操作按钮禁用，避免重复提交。
- 生成成功后清空输入框；生成失败时保留内容，方便用户修改后重试。
- 已采用方向后仍禁止重新生成。

## 数据流

前端将重新生成请求改为：

```json
{
  "guidance": "本次补充要求"
}
```

后端使用严格请求模型校验 `guidance`，拒绝多余字段。`FileProjectStore` 将补充要求作为方法参数传给方向生成器，但不写入任何项目文件。生成器的提示上下文仅包含题材、原始灵感、可选工作书名和本次补充要求，不加载角色卡、历史章节或技能。

## 错误处理

- 超过 1000 字或请求结构错误：返回 422。
- 运行时、模型响应或方向结构错误：维持现有 502 行为。
- 失败时保留已有候选文件和用户输入。
- 方向已采用：维持现有禁止重新生成行为。

## 测试

- 后端请求会去除补充要求首尾空白，并拒绝超长及多余字段。
- 生成器提示包含补充要求，但项目文件中不保存该文本。
- 无补充要求时保持原有生成行为。
- 页面只在重新生成场景显示输入框，并将内容传给 API。
- 成功后清空，失败后保留；请求期间禁止重复操作。
- 现有新建小说、首次生成、选择方向和移动端测试继续通过。
