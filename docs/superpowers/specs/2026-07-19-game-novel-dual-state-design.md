# 网游角色卡双状态设计

## 目标

网游题材同时存在现实线和游戏线。角色卡必须让模型明确区分两条线，避免把现实余额、现实身份、游戏等级、背包和任务混在一起。其他小说类型不加载网游专用状态。

## 数据边界

通用角色卡继续保存人物本身的信息：姓名、年龄、来历、性格、目标、关系、说话方式、行为习惯和角色发展。

只有网游类型角色卡增加两个可选对象：

- `real_state`：现实身份、工作、住处、现实目标、现实压力、现实余额、现实关系和最近变化。
- `game_state`：游戏 ID、等级、经验、职业、生命、法力、装备、背包、游戏货币、任务、游戏关系和最近变化。

两个状态都允许保存 `current` 和 `recent_changes`。`current` 是当前事实，`recent_changes` 只记录最近章节已经发生的变化，不能把计划当成事实。

## 写作包提取

写作包不再把双状态完整混入每章提示词：

- 现实场景只提取 `real_state`。
- 游戏场景只提取 `game_state`。
- 场景发生切换时同时提取两者，并增加一条明确的影响关系，例如“游戏收益尚未到账，现实余额不变”。
- 角色卡仍按本章出场人物提取，不发送全量人物库。

## 状态同步

章节提交后，现实变化只由正文中明确的到账、提现、卖币或支付行为触发；游戏变化由游戏内行动和账本触发。任何一条线的变化不能自动写入另一条线。

旧项目兼容规则：

- 现有 `game_panel` 映射到 `game_state.current`。
- 现有角色顶层现实字段保留，并映射到 `real_state.current`。
- 旧数据不强制迁移，读取时兼容，保存角色卡时逐步补齐双状态。

## 题材隔离

网游状态只由 `game_webnovel` 类型加载。都市、玄幻、仙侠和其他类型继续使用通用角色卡，不出现 `game_state`、背包、等级或游戏货币字段。

## 验收标准

1. 网游主角角色卡能同时展示现实状态和游戏状态。
2. 游戏场景写作包不带现实余额等无关字段，现实场景不带背包和等级等游戏字段。
3. 章节状态更新不会把游戏货币写入现实余额，也不会把现实到账写成游戏货币。
4. 旧项目读取和现有角色卡页面不报错。
5. 非网游题材的角色卡和写作包不出现网游字段。
