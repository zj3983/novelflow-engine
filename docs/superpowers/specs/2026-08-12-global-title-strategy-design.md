# 全局书名与章节标题策略设计

## 目标

为所有小说题材提供统一、可复用的标题生成方法，同时防止网游词汇串入玄幻、都市、科幻等项目。

标题策略只负责书名与章节标题，不参与正文写作，不改变已经确认的正文内容。

## 全局规则

### 书名

开书阶段根据以下信息生成候选书名：

- 核心卖点、特殊能力或故事机制。
- 主角身份、处境或反差。
- 读者可以期待的爽点、危机或后果。

结构参考为“核心卖点/能力 + 身份或反差 + 爽点或后果”，但不是固定句式。模型必须根据中文口语习惯调整语序，不得机械拼接三段标签。

### 章节标题

章节标题从本章细纲的具体事件中提取，优先选择以下一种功能：

- 危机：指出即将发生的具体麻烦。
- 反击：指出主角采取的关键动作或造成的结果。
- 反差：突出人物身份、认知或结果之间的落差。
- 悬念：暴露新的事实、倒计时、人物或异常，但不提前解释答案。
- 转折：指出本章发生的不可逆变化。

标题必须对应本章真实发生的事件。不得只写“新的开始”“危机来临”等抽象概括，也不得为了吸引点击虚构正文中不存在的内容。

## 题材适配

全局策略读取当前项目的题材配置，只使用该题材允许的词汇和叙事对象。

- 网游：首杀、副本、Boss、全服、公会、技能、等级。
- 玄幻/仙侠：境界、宗门、功法、天劫、秘境、因果。
- 都市：身份、职业、利益、关系、合同、证据。
- 科幻：实验、协议、权限、殖民地、倒计时、失控事件。
- 其他题材：从题材模块提供的术语表读取，不猜测为网游或修仙。

题材模块只提供可用词汇和常见冲突，不提供固定标题。全局策略负责组合与筛选。

## 示例

示例用于学习结构，不允许照抄人物、物品或句子。

### 网游书名

- `《网游：满级魔龙？给我回滚成野狗！》`
- `《让你玩游戏，你把世界底层代码黑了？》`
- `《身为测试员，在游戏里卡点Bug很合理吧》`
- `《说好的虚拟网游，你怎么自带控制台？》`
- `《地球旧服即将删档，我成了唯一管理员》`
- `《全人类强制转服，只有我在卡Bug》`

### 网游章节标题

- 危机：`《开局刷五十级Boss？这游戏我不玩了！》`
- 反击：`《管你是龙是虫，给我退回去！》`
- 震惊：`《全服疯了！那个首杀的一级萌新是谁？》`
- 悬念：`《倒计时三百六十五天，即将被格式化的地球》`

其他题材可以学习“具体事件 + 反差/后果”的结构，但不得复用“全服、Boss、Bug”等网游词汇。

## 防模板化限制

- 不要求每章使用问号、感叹号或震惊体。
- 相邻三章不得连续采用同一种标题句式。
- 不强制使用“全场震惊”“所有人都疯了”等群体反应。
- 标题默认不超过二十个汉字；专有名词较长时可以适度放宽。
- 章节编号由界面统一显示，生成标题本身不重复写“第 X 章”。
- 已有人工标题不自动覆盖，重新生成时必须由用户明确触发。

## 模块边界

新增独立的全局标题策略模块，提供两个入口：

1. `generate_book_title_candidates`：供开书和书名重生成调用。
2. `build_chapter_title_guidance`：供总纲、阶段大纲和章节细纲生成调用。

正文写手只读取已经确定的书名和章节标题，不读取标题公式和示例。审稿只检查标题与正文是否一致，不因标题不够夸张而阻止正文保存。

## 数据流

```text
开书输入 + 题材配置 + 核心设定
  -> 全局书名策略
  -> 书名候选
  -> 用户确认或采用默认候选

总纲/阶段大纲 + 本章细纲 + 题材配置
  -> 全局章节标题策略
  -> 章节标题
  -> 导演读取已定标题与细纲
  -> 写手只写正文
```

## 错误处理

- 题材配置缺失：使用不含专属术语的通用标题规则。
- 本章细纲缺失：不生成章节标题，先引导用户补全细纲。
- 标题与本章事件不一致：标记为标题问题，不触发正文自动改稿。
- 模型返回空标题：使用本章最具体的行动或结果生成保底标题，不使用“未命名”进入正式大纲。

## 测试与验收

- 网游、玄幻、都市和科幻项目分别生成书名候选，不能出现跨题材词汇。
- 同一组十章细纲生成标题时，不得连续三章采用相同问句或感叹句结构。
- 章节标题必须能在对应细纲中找到事件依据。
- 写手上下文中只能看到最终标题，不能看到书名公式、章节标题公式或示例。
- 人工修改过的标题不会被后续正文生成覆盖。
- 未生成细纲时不会顺带生成正文或临时标题。
