# 新小说创建入口设计

## 目标

在作品列表提供明确的“新建小说”入口，并让新项目直接使用当前文件项目、题材模块、三级大纲和 Skills 流程，不再创建功能不完整的旧数据库项目。

新建过程保持简短。用户不需要一次填完世界观、人物卡和大纲，也不会在创建时直接生成正文。

## 用户流程

作品列表页右上角增加“新建小说”按钮，进入 `/projects/new`。页面提供两个互斥模式。

### 建立空白小说

必填项：

- 小说名
- 小说类型

提交后立即创建文件项目，并进入该项目的总纲页面。世界观、角色卡、阶段大纲和章节大纲仍在各自页面维护。

### 从灵感开书

必填项：

- 小说类型
- 一句话想法

小说名可选，未填写时暂用“未命名作品”。提交后先创建草稿文件项目，再进入 `/projects/{id}/setup`。

开书准备页调用模型生成三套候选方向。每套只展示：

- 暂定书名
- 核心看点
- 主角目标
- 主要冲突
- 成长路线
- 开篇承诺

用户选择一套后，系统更新项目标题，并将候选方向转换为总纲的五个字段。随后进入总纲页面继续修改。候选内容不直接生成角色卡、世界观或章节正文。

候选不满意时可以重新生成；模型不可用时保留已经创建的项目和原始想法，允许重试或改为手动填写总纲。

## 数据边界

新项目使用不可读的稳定 ID，例如 `p-<uuid>`。目录名只来自该 ID，不使用用户输入拼接路径。修改书名不会改变项目 ID 或目录。

项目目录由新的文件项目初始化器一次创建：

```text
data/exported-projects/<project-id>/
  .story-system/
    MASTER_SETTING.json
  .webnovel/
    project.json
    state.json
    outline.json
    opening_brief.json        # 仅灵感模式存在
    opening_directions.json   # 生成候选后存在
  chapters/
  commits/
  reviews/
```

各文件职责保持独立：

- `project.json`：标题、题材、状态、启用的 Skills 等项目元数据。
- `state.json`：当前章节和运行状态。新书从第 0 章开始，不包含人物、物品或剧情事实。
- `outline.json`：三级大纲。空白模式写入合法空结构；选择灵感方向后只更新总纲。
- `opening_brief.json`：用户输入的一句话想法和创建模式。
- `opening_directions.json`：候选方向、生成状态和最终选择，仅用于开书准备。
- 人物、世界观和正文不会写入上述灵感文件，也不会在创建时伪造。

初始化过程先写入同级临时目录，所有必需文件校验成功后再原子改名。任何一步失败都清理临时目录，不留下半个项目。

## API

### 创建文件项目

`POST /file-projects`

请求：

```json
{
  "mode": "blank | inspiration",
  "title": "可选或必填，取决于 mode",
  "novel_type_id": "xuanhuan",
  "idea": "灵感模式必填"
}
```

规则：

- `blank` 模式要求标题；`inspiration` 模式要求一句话想法。
- 题材必须来自服务端 `novel_type_catalog`。
- 标题和想法去除首尾空白并限制长度。
- 返回 `ProjectResponse`、公开的 `file:` 项目 ID 和下一步页面。
- 不复用旧的 `POST /projects` 数据库创建接口。

### 生成候选方向

`POST /file-projects/{project_id}/opening-directions`

读取 `opening_brief.json` 和该项目的题材模块，只要求模型返回三套结构化候选。提示词不读取其他小说内容，也不加载全部 Skills、角色卡或世界状态。

生成结果经过结构校验后原子写入。模型输出不合法时返回可重试错误，不保存残缺候选。

### 选择候选方向

`POST /file-projects/{project_id}/opening-directions/{direction_id}/select`

选择操作更新：

- `project.json` 的标题和开书状态
- `outline.json` 的总纲五字段
- `opening_directions.json` 的已选择状态

阶段大纲、章节大纲、世界观和角色卡保持为空。选择成功后返回总纲页面地址。

## 前端

作品列表页无论是否已有作品，都显示“新建小说”。空列表提示中也提供同一个入口。

`/projects/new` 使用简洁表单：

- 顶部用分段控件选择“从灵感开书”或“建立空白小说”。
- 题材使用现有 `NOVEL_TYPE_OPTIONS`。
- 只显示当前模式需要的字段。
- 提交期间锁定按钮，成功后按后端返回地址跳转。
- API 错误原样展示为可理解的中文提示，不使用前端 mock 假装创建成功。

`/projects/{id}/setup` 只负责生成和选择方向。它不是世界观页、人物页或大纲编辑器。选择完成后进入已有三级大纲页面。

## 状态与恢复

文件项目的开书状态使用明确阶段：

- `draft`：空白项目已建立，可以手动编辑。
- `idea_pending`：灵感项目已建立，尚未生成候选。
- `direction_ready`：候选已生成，等待选择。
- `outlining`：方向已选择，进入总纲编辑。

刷新页面时根据落盘状态恢复，不依赖浏览器内存。重复点击生成可以覆盖未选择的候选；已经选择后再次生成必须先明确取消选择，首版界面不提供该操作。

## 错误处理

- 标题重复不构成冲突，因为项目 ID 独立生成。
- 路径、题材和请求字段在后端校验，前端校验只用于即时提示。
- 初始化失败不出现在项目列表。
- 模型失败不删除项目，用户可以重试或手动进入总纲。
- 选择不存在或已经失效的候选返回 `409/404`，不修改任何文件。
- 所有多文件写入先准备完整内容，再按可恢复顺序替换；选择失败时不能出现“标题已改但总纲未改”的状态。

## 测试

后端测试覆盖：

- 两种模式的字段校验和题材校验
- 新项目目录及最小 JSON 内容
- ID 与用户标题隔离，阻止路径穿越
- 初始化中途失败时无残留目录
- 三套候选的结构校验和错误回退
- 选择候选后只更新项目标题、总纲和选择状态
- 新项目可被列表、详情、总纲和写作包接口读取

前端测试覆盖：

- 项目列表始终显示新建入口
- 两种模式切换时字段正确变化
- 空白模式创建后进入总纲
- 灵感模式创建后进入开书准备
- 候选生成、重试、选择和模型失败提示

最后运行后端全量测试、前端生产构建和新建流程的 Playwright 定向测试。测试项目使用临时导出目录，不污染现有小说。

## 不在本次范围

- 创建时自动生成角色卡、世界观、阶段大纲或正文
- 系列作品和跨书共享设定
- 用户自定义项目初始化工作流
- 从旧数据库项目迁移为文件项目
- 删除、复制或归档项目
