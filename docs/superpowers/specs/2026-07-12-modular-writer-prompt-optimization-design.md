# 模块化正文提示词优化设计

## 目标

在不增加写作流程长度的前提下，重新组织正文生成提示词。模型拿到的是一份短而清楚的写作材料，而不是由多份规则拼成的审稿清单。

本次只优化正文生成和改稿时的提示词装配，不重做世界模拟、审稿系统、Skill 平台或前端页面。

## 当前问题

1. 白描、自然对话、反 AI 表达等要求同时出现在任务书、风格模块、Skill 摘要和总提示词中，内容重复。
2. 负面禁令和示例过多，模型容易逐条规避，正文反而生硬。
3. 世界事实、人物资料和写作方法混在同一段 JSON 或长文本里，模型不容易判断信息用途。
4. 对话规则强调完整和推进，但缺少本场人物为什么开口、说话时是什么关系和情绪。
5. 部分提示词仍带有后台字段、检查口吻和固定句式，影响正文语言。

## 设计原则

### 一、事实与写法分开

- 世界观、大纲和连续性模块只回答“故事里已经确定了什么”。
- 角色模块只回答“本章出场人物会怎样选择和说话”。
- 本章方向只回答“这一章发生什么变化”。
- 写作方法只回答“这些内容怎样写成自然中文正文”。
- 审稿意见只在改稿阶段注入，不进入首次写作提示词。

### 二、按需提取

正文阶段只加载：

1. 与本章冲突直接相关的世界事实和大纲范围。
2. 本章出场人物的当前目标、顾虑、关系、情绪和说话方式。
3. 本章目标、主要阻力、关键变化和结尾承接。
4. 一份通用、简短的正文写法说明。

不把完整世界观、完整角色库、完整伏笔表或原始计划字典发送给写作模型。

### 三、采用正向写法

正文写法模块压缩为以下方法：

- 使用第三人称有限视角，一场戏跟随一个观察人物。
- 从正在发生的事情写起，让人物面对具体问题并作出选择。
- 动作连续写清原因和结果，不把完整动作切成名词式短句。
- 对话符合人物关系和当时目的，有正常的接话、解释和情绪变化。
- 心理和环境只在影响选择、关系或现场状态时出现。
- 长短句随内容自然变化，保持现代中文语序。
- 规则和设定通过人物行动、反馈与后果显露，不写成说明书。

保留少量必要保护线，例如事实不能冲突、不能泄露后台字段、输出只能是小说正文。删除全面禁用某类连接词、要求每句台词搭配动作等绝对规定。

## 提示词结构

正文提示词固定为五块：

1. **输出要求**：连续小说正文、目标篇幅、视角。
2. **本章方向**：目标、阻力、变化、结尾承接。
3. **本章事实**：只列当前场景会用到的连续性事实。
4. **出场人物**：目标、顾虑、关系、情绪、语言习惯。
5. **正文写法**：一份不重复的短方法说明。

题材 Skill 可以补充题材知识，但不能再次注入通用风格规则。风格 Skill 启用后替换默认表达方法，不与默认模块叠加。

## 数据同步

沿用现有世界观、角色卡、大纲、章节状态和伏笔数据。章节写完后的状态更新仍由现有记忆和连续性流程处理。本次不接受“模型自己永久记忆”的假设，所有长期信息继续落到项目数据中。

## 错误处理

- 某个角色缺少完整角色卡时，只提供已有资料，不临时编造与大纲冲突的背景。
- 本章方向缺失时，使用大纲允许范围生成最小推进目标，不把内部字段直接交给写作模型。
- Skill 内容与项目事实冲突时，以项目事实为准。
- 提示词超过预算时，先缩减历史和示例，不删除本章事实与人物关系。

## 验证

增加或调整测试，确保：

1. 正文提示词五块职责清楚，没有后台 JSON 键名。
2. 通用风格要求只出现一次。
3. 写作提示词不包含原始完整世界观、角色库和伏笔表。
4. 不强制每句台词附带动作、表情或心理。
5. 不全面禁止“但是”“虽然”等正常中文连接词。
6. 角色模块只包含本章相关人物。
7. 现有网游和修仙项目都能生成对应题材提示词。
8. 相关 Python 测试和前端构建继续通过。

## 非目标

- 不新增 Agent。
- 不增加一次额外模型调用。
- 不恢复分段生成。
- 不扩大审稿报告。
- 不把两份抖音提示词原文加入项目。
