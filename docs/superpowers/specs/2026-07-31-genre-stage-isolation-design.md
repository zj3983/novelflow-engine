# 题材阶段隔离设计

## 目标

把导演、写手、审稿和改稿阶段中的网游专用提示词与判断从 `orchestrator.py` 迁出。通用编排器只负责流程调度和数据传递，不再直接认识游戏 ID、等级、职业、背包、装备、怪物面板、任务、交易、属性点或玩家/NPC 规则。

迁移后，非网游项目的任何阶段都不能读取网游提示词。新增题材时，可以独立提供自己的阶段规则，不需要继续修改编排器。

## 模块边界

新增 `packages/story_core/genre_stages/`：

```text
genre_stages/
  base.py
  registry.py
  generic.py
  game_webnovel/
    __init__.py
    director.py
    writer.py
    review.py
    revision.py
```

`base.py` 定义轻量的 `GenreStageProfile` 接口。每个题材配置可以提供：

- 导演模板选择与题材补充要求
- 写手题材事实、写法和输出要求
- 题材专用审稿检查
- 题材专用改稿说明
- 题材专用的提示词清理与兼容处理

`registry.py` 根据项目的规范化小说类型返回一个 profile。没有专用实现时返回 `generic`，不做动态加载，也不增加新的 Agent。

## 编排器职责

`orchestrator.py` 最终只保留以下职责：

1. 读取当前作品、章节计划、角色和连续性资料。
2. 从 registry 获取当前题材 profile。
3. 调用 profile 生成导演、写手、审稿和改稿阶段的题材内容。
4. 组装通用模板、调用模型、验证通用返回结构并保存产物。

提示词组装路径内不再使用 `is_game` 分支，也不再出现网游专用文字。通用返回结构仍保留目标、阻碍、行动、结果、代价、状态变化和章末钩子。

## 网游模块职责

网游阶段包接管以下内容：

- 游戏 ID、职业、等级、经验、属性和加点
- 背包、货币、装备、耐久、技能和消耗品
- 任务、掉落、怪物面板、交易与官方兑换
- 玩家、NPC、公会和市场的信息可见性
- 越级、转职、异常收益和现实/游戏双线连续性
- 网游第一章及前期节奏的专用检查
- 上述问题对应的改稿要求与旧术语清理

已有 `web_game_*` 模块继续作为网游包内部依赖，不再由通用编排器直接拼接它们的提示词。

## 运行流程

```text
作品类型
  -> genre stage registry
  -> generic 或 game_webnovel profile
  -> 导演题材内容
  -> 写手题材内容
  -> 审稿题材检查
  -> 改稿题材说明
```

每一步仍在工作台记录读取内容和产物来源，但来源显示为具体题材模块，例如“网游写手规则”，而不是笼统显示在通用编排器中。

## 兼容策略

- 保持现有章节生成 API 和模型返回 JSON 结构不变。
- 保持已有网游项目行为，先迁移再删除旧分支。
- 项目级提示词覆盖继续生效，但只能覆盖当前阶段模板，不能改变题材适用范围。
- 历史日志和历史提示词快照不回写；新生成任务使用新模块。
- 不启用 Skills，不增加新的生成步骤或模型调用。

## 验证

增加三类自动检查：

1. 通用、仙侠、玄幻、都市项目的导演、写手、审稿和改稿提示词不得出现网游专用词。
2. 网游项目仍能获得游戏账本、怪物面板、任务交易和属性加点规则。
3. `orchestrator.py` 的阶段提示词组装区域不得出现网游专用文字或 `is_game` 分支。

运行现有提示词、编排器、审稿、改稿和工作台定向测试，并分别生成一个网游项目和一个非网游项目的实际调用快照进行对照。
