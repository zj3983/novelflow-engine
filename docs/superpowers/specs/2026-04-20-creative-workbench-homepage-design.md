# 小说工作台首页改版设计稿

日期：2026-04-20
项目：Novel Autogrowth Engine / XiaoShuoFish
范围：`apps/web` 首页与工作台信息架构、视觉方向、关键交互

## 1. 目标

本次首页改版的目标不是做一个“启动页”，而是做一个真正可长期使用的创作工作台。

用户打开首页后，第一眼应该先看到：

- 当前故事推进到了哪里
- 最近生成过哪些章节
- 角色、伏笔、冲突有没有跑偏
- 下一步是继续生成、回看历史，还是进入配置

首页定位为“创作工具型”的写作驾驶台，强调：

- 清晰
- 稳定
- 长时间使用不累
- 故事状态和章节历史一眼能懂

导入书籍与模型/API 配置仍然重要，但不再占据首页主舞台，只保留为中等显眼的快捷入口。

## 2. 设计结论

采用“经典写作台 + 顶部状态总览”的方案。

这是一个三段式布局：

- 顶部：项目与状态总览条
- 左侧：导航与快捷入口
- 中间：故事状态和历史章节主内容
- 右侧：角色状态、运行记录、风险提醒

默认首页主焦点是“当前故事状态 + 历史章节”，而不是“导入”或“立即生成”。

## 3. 页面结构

### 3.1 顶部状态条

顶部区域承担两个职责：

- 明确当前书籍和当前进度
- 给出最常用的创作动作

建议包含以下内容：

- 书名
- 卷/章进度
- 最近一次生成时间
- 当前工作状态摘要
- 主按钮：`继续生成下一章`
- 次按钮：`查看配置`

状态条要横向紧凑，不做大面积 Banner。它是工作台，而不是宣传页。

### 3.2 左侧导航栏

左侧导航承担“切换视角”和“快速进入管理动作”的职责。

建议项目：

- 工作台
- 章节目录
- 角色状态
- 故事摘要
- 书籍导入
- 配置中心

其中：

- `书籍导入`
- `配置中心`

需要看得见，但不是首页第一视觉重心。

### 3.3 中央主工作区

中央区域是首页核心，采用上下两层。

上半区：故事总览卡组

建议包含：

- 当前推进章节
- 当前焦点
- 主冲突
- 次冲突
- 关键伏笔
- 记忆摘要

这部分应该是“扫一眼就懂”的摘要，不要做成冗长文档块。每张卡片都只显示当前最关键的信息，必要时提供“展开详情”。

下半区：历史章节流

以章节卡片列表或时间线形式展示已生成章节，每张卡片建议包含：

- 章节号
- 章节标题
- 一句话摘要
- 涉及角色
- 新增变化
- 打开详情按钮

章节历史是首页的第二主角，因为用户需要频繁回看和确认剧情是否在正确方向上演化。

### 3.4 右侧辅助栏

右侧作为“状态侧脑”，负责提醒和观察，不承担主流程。

建议包含：

- 角色状态面板
- 最近运行记录
- 风险与提醒

风险与提醒的典型内容：

- 新角色待确认
- 某条伏笔长时间未回收
- 某角色目标长期未推进
- 最近几章节奏过于重复

## 4. 视觉风格

整体风格选择“创作工具型”，不做科幻控制台，也不做营销 Landing Page。

### 4.1 视觉关键词

- 纸面感
- 编辑台
- 稳定秩序
- 温暖而克制

### 4.2 色彩建议

主色不使用高饱和紫色，也不走纯黑深色路线。

推荐方向：

- 背景：暖灰、纸白、浅米色
- 主强调色：墨蓝、黛青、深茶色
- 状态点缀：暗金、砖红、松绿色

这样既保留创作氛围，也能长时间阅读。

### 4.3 字体方向

避免默认系统感太强的无聊组合。

建议：

- 标题：更有书卷感的中文衬线或类衬线风格
- 正文与面板：高可读性的现代中文字体
- 数据与标签：更克制、窄一点的 UI 字体风格

核心原则是“像专业创作工具”，而不是“像企业后台”。

### 4.4 组件风格

建议卡片具备以下特征：

- 轻边框
- 柔和阴影
- 明确层级
- 适度留白

按钮优先级清晰：

- 主按钮明显但不刺眼
- 次按钮低存在感
- 危险或清空类操作必须克制

## 5. 关键交互

### 5.1 首页默认路径

用户进入首页后的默认行为路径：

1. 看当前推进状态
2. 扫一眼最近章节
3. 看右侧提醒是否异常
4. 决定继续生成、回看章节，还是调整配置

首页不应逼用户先填写表单。

### 5.2 继续生成

点击 `继续生成下一章` 后：

- 在当前页就地反馈生成中状态
- 右侧运行记录同步刷新
- 生成完成后历史章节区插入新章节卡片
- 故事总览卡组同步更新

不要跳转到单独的“生成结果页”，避免打断工作流。

### 5.3 查看历史章节

点击历史章节卡片后：

- 中央区域切换为章节详情视图，或抽屉式展开
- 保留返回历史流的上下文
- 章节详情中可查看正文、摘要、涉及角色、伏笔变化

重点是“回看方便”，而不是“切屏很多”。

### 5.4 导入与配置入口

导入和配置入口放在：

- 左侧导航
- 顶部次按钮

它们应当是清晰可达的辅助动作，而不是首页主按钮群。

## 6. 组件拆分建议

推荐拆成以下 UI 单元，避免首页文件再次膨胀：

- `WorkbenchTopBar`
- `WorkbenchNavRail`
- `StoryOverviewGrid`
- `OverviewCard`
- `ChapterHistoryFeed`
- `ChapterHistoryCard`
- `WorkbenchSidePanel`
- `RuntimeActivityCard`
- `StoryRiskCard`

现有组件可以优先复用或改造：

- `AppShell`
- `AppSidebarNav`
- `ChapterBundleView`
- `StorySidebar`
- `BookImportPanel`
- `workbench/WorkbenchShell`

目标不是推翻现有结构，而是在已有两页结构上，把首页真正做成“工作台”。

## 7. 响应式策略

桌面端优先采用三栏布局。

平板和较窄窗口时：

- 右侧辅助栏收纳到折叠面板
- 中央主区保留为第一优先级

移动端时：

- 顶部状态条保留
- 左侧导航改为抽屉
- 中央改为纵向流
- 右侧辅助信息下沉到底部折叠区

无论屏幕尺寸如何变化，都要保证：

- 当前推进状态清晰
- 历史章节可访问
- 继续生成入口不丢失

## 8. 文案原则

首页文案需要统一成中文，并且尽量减少技术腔。

推荐原则：

- 用户看见的是“故事”“章节”“角色”“运行记录”
- 尽量少直接暴露 `mode`、`strategy`、`runtime` 这类词
- 技术配置只留在配置中心

首页是创作界面，不是开发者控制台。

## 9. 风险与边界

本次改版不包含：

- 重做整个配置中心的底层逻辑
- 重写章节生成后端
- 新增复杂多窗口编辑器

本次改版要避免的问题：

- 首页像后台管理系统
- 首页仍以导入面板为第一视觉中心
- 首页信息很多，但没有明显主次
- 历史章节不能快速回看

## 10. 验收标准

设计落地后，应满足以下标准：

- 用户打开首页，能在 3 秒内知道故事进度和当前状态
- 用户能在首页直接进入最近章节回看
- 用户能在首页直接继续生成下一章
- 导入和配置可快速进入，但不抢首页主焦点
- 全部首页核心文案统一为中文
- 桌面端与移动端都保持主要工作流可用

## 11. 推荐实施顺序

建议按以下顺序落地：

1. 调整首页信息架构与布局骨架
2. 将故事总览卡组和章节历史流放到首页主区
3. 重做右侧辅助栏为角色/运行/风险组合
4. 统一首页中文文案与视觉样式
5. 补充桌面与移动端测试

## 12. 结论

这次首页应该从“功能入口集合”升级成“创作工作台”。

首页的第一职责不是让用户配置，而是让用户理解故事现在在哪里，并且顺畅地继续推进下一章。

采用“创作工具型 + 混合总览 + 中等显眼辅助入口”的方案，最适合这个项目当前阶段，也最贴近用户真实使用路径。
