# 小说封面与作品简介设计

## 目标

为文件型小说项目增加两项彼此独立的作品包装能力：

- 生成、编辑和保存适合番茄小说上架的作品简介。
- 生成可编辑的封面提示词；配置图片模型时直接生成无字底图，再由系统叠加清晰书名并输出可下载封面。

功能入口位于作品概览页。封面与简介采用两个独立卡片，各自拥有生成、编辑、重做和错误状态。任一功能失败不得阻塞或覆盖另一项功能。

## 已确认的产品决定

1. 封面与简介完全独立生成，不提供捆绑的“生成作品包装”操作。
2. 每次封面生成只请求一张图片，不提供多候选选择或封面历史库。
3. 图片模型只生成无字底图；中文书名由系统确定性叠加。
4. 封面不显示作者名或“AI 生成”标记。
5. 图片模型未配置或不兼容时，功能仍生成并保存可复制的封面提示词。
6. 简介采用番茄风结构，不使用传统完整故事梗概。
7. 文本生成复用当前文本模型配置；封面图片使用独立的全局图片模型配置。
8. 首版只服务现有文件型项目，不扩展 SQLite 旧项目或自动在创建小说时生成。

## 番茄简介调研结论

番茄小说当前阅读榜中的高热作品普遍使用以下结构：

- 开头用题材标签帮助目标读者快速判断。
- 第一段立即给出主角身份反差、特殊能力、金手指或生死困境。
- 中段常用“好消息/坏消息”、短对话或小剧场展示核心冲突。
- 重点承诺阅读体验和主要爽点，而非复述全部世界设定与完整主线。
- 结尾可以说明节奏、感情线等阅读预期，但不使用无信息量的空泛问句。

番茄金番作者的公开课程也把常用简介分为三类：概括主线并留悬念、从冲突直接切入、截取精彩片段写成小剧场。

调研来源：

- 番茄小说阅读榜：https://fanqienovel.com/rank/1
- 金番作者简介课程转载：https://www.xinenw.com/44601.html

## 用户界面

### 作品概览页

在现有状态卡片之后、章节列表之前增加两张作品包装卡片。宽屏时左右排列，窄屏时上下排列。

#### 封面卡片

空状态显示：

- 将读取哪些小说信息。
- “生成封面”主按钮。
- 当前图片模型配置状态。

已有封面时显示：

- 3:4 封面预览。
- 图片格式、尺寸和更新时间。
- “重新生成”“编辑提示词”“下载”操作。

图片模型未配置或调用失败，但提示词生成成功时显示：

- 已生成的封面提示词。
- “复制提示词”“编辑提示词”“前往配置”“重试生图”操作。

#### 简介卡片

空状态显示“生成简介”。已有简介时显示题材标签和完整正文，并提供：

- “重新生成”：可先填写不超过 1000 字的指导语。
- “编辑简介”：编辑标签和正文后保存。
- “复制”：复制可直接上架的标签与正文。

### 独立交互状态

封面与简介分别维护 `idle`、`generating`、`saving` 和 `error` 状态。操作只锁定当前卡片，另一张卡片继续可用。重复点击由前端请求锁拦截。

## 数据模型

在 `.webnovel/project.json` 增加可选的 `publishing_assets`：

```json
{
  "publishing_assets": {
    "schema_version": "publishing-assets/v1",
    "synopsis": {
      "tags": ["穿越", "成长", "无系统"],
      "body": "……",
      "format": "fanqie",
      "updated_at": "2026-07-31T00:00:00Z"
    },
    "cover": {
      "prompt": "……",
      "image_version": "20260731T000000Z",
      "width": 768,
      "height": 1024,
      "mime_type": "image/png",
      "model": "configured-image-model",
      "rendered_title": "归墟行舟",
      "updated_at": "2026-07-31T00:00:00Z"
    }
  }
}
```

约束：

- `publishing_assets` 对旧项目可选；读取缺失字段时返回空状态。
- 图片二进制和 API 密钥不得写入项目 JSON。
- 只生成出提示词时，`cover.prompt` 与 `updated_at` 必须保存，图片版本、尺寸、格式和模型字段可以缺省。
- 成功输出最终封面时保存 `cover.rendered_title`，用于识别项目书名是否已变化并提示重新排版。
- `synopsis.tags` 保存 4 至 8 个去重后的非空标签。
- `synopsis.body` 保存 200 至 450 个中文字符的正文；人工编辑时仍执行非空和最大长度校验，但不强制用户保持模型生成长度下限。
- 时间使用 UTC ISO 8601 字符串。

封面文件位于：

```text
.webnovel/assets/cover-base.png
.webnovel/assets/cover.png
```

`cover-base.png` 是无字底图，`cover.png` 是叠加书名后的最终文件。保留底图后，修改书名时可以重新排版而不再次调用图片模型。首版只维护当前版本；新封面通过原子替换覆盖旧文件。

## 组件与职责

### `publishing_assets`

新增聚合模块负责：

- 从项目文件构建稳定、限长的作品包装上下文。
- 调用简介生成器并校验结构化结果。
- 调用封面提示词生成器。
- 在图片模型可用时调用图片提供器。
- 校验、裁切和排版封面。
- 原子保存项目元数据与图片文件。

该模块不处理 HTTP、React 状态或全局配置表单。

### 简介生成器

输入：

- 书名和小说类型。
- 已选开书方向或开书灵感。
- 主角卡。
- 核心世界规则。
- 当前总纲与卷纲摘要。
- 可选用户指导语。

不得把整本正文或全部章节对象装入提示词。缺少后期大纲的新项目仍可使用开书方向、灵感与世界摘要生成。

输出固定为 JSON：

- `tags`：4 至 8 个题材标签。
- `body`：200 至 450 字简介。
- `visual_hook`：只供封面提示词生成器使用，不在界面额外展示。
- `pattern`：`conflict`、`contrast` 或 `micro_scene`。

提示词要求模型选择最适合当前作品的一种模式，必须体现主角身份、核心优势、眼前危机和主要阅读爽点；禁止完整剧透、设定罗列、空泛问句与模板化赞美。

服务端校验失败时允许一次结构化修复。修复仍失败则返回错误，不覆盖当前简介。

### 封面提示词生成器

从与简介相同的作品上下文和可用的 `visual_hook` 提炼中文图片提示词。提示词必须包含：

- 单一清晰主体或核心场景。
- 与小说类型匹配的视觉风格、色彩、光线和氛围。
- 适合 3:4 小说封面的构图说明。
- 为书名预留低细节、对比稳定的干净区域。
- “无文字、无字母、无标志、无水印”的明确负向要求。

用户可以编辑并保存提示词。编辑提示词不修改现有封面，只有再次生成图片时才替换。

### 图片提供器

新增独立图片运行时配置：

- `api_key`
- `base_url`
- `model`
- `enabled`

首版支持 OpenAI 兼容的 `/images/generations` 接口，并请求单张 Base64 图片。文本模型配置与图片配置不得互相覆盖。

仅接受 Base64 图片结果。若兼容服务只返回外部 URL，则返回 `unsupported_image_response` 并保留提示词，不由服务端抓取任意 URL。

图片响应校验：

- 仅接受 PNG、JPEG 或 WebP。
- 解码后限制像素数量和文件字节数。
- 拒绝损坏、空白或无法识别的图片。

### 封面排版器

使用 Pillow 完成：

1. 按中心安全区域裁切并缩放至 768×1024。
2. 短书名优先竖排；长书名自动分行并缩小字号。
3. 在提示词预留区域放置书名。
4. 使用轻微描边或阴影保证复杂背景上的可读性。
5. 输出 PNG，不添加作者名或任何 AI 标记。

字体解析顺序：

1. `NOVEL_COVER_FONT_PATH` 指定的字体。
2. Windows 常见中文字体。
3. Linux 常见 Noto/思源中文字体。

找不到支持中文的字体时返回 `cover_font_unavailable`，保留无字底图与提示词，不输出包含乱码的最终封面。

## API

### 读取

现有文件项目响应增加 `publishing_assets`，旧项目返回空结构。

```text
GET /file-projects/{project_id}/publishing/cover.png
```

返回当前最终封面；不存在时返回 404。响应带版本化 ETag 和适合本地资产的缓存头。`?download=1` 使用 `Content-Disposition: attachment`，否则以内联图片返回。

### 简介

```text
POST /file-projects/{project_id}/publishing/synopsis
PUT  /file-projects/{project_id}/publishing/synopsis
```

生成请求接受可选 `guidance`。编辑请求接受 `tags` 与 `body`。成功响应返回完整 `synopsis`。

### 封面

```text
POST /file-projects/{project_id}/publishing/cover
PUT  /file-projects/{project_id}/publishing/cover-prompt
POST /file-projects/{project_id}/publishing/cover/render-title
```

生成封面请求接受可选 `guidance`。处理顺序为：生成或读取提示词、保存提示词、检查图片配置、生成底图、校验图片、排版书名、原子保存最终资产、更新项目元数据。

图片配置不可用时，生成封面端点返回成功的 `prompt_ready` 状态，而不是把已成功生成提示词视为整体失败。

`render-title` 只读取现有底图和当前书名，不调用任何模型。

## 全局配置

在现有配置页增加“封面图片模型”区域，与文本模型配置分开。页面支持：

- 启用或停用图片生成。
- 编辑 API 地址、模型名和密钥。
- 显示密钥是否已配置，不回传明文。
- 校验必需字段并保存。

图片密钥复用当前 Windows 安全存储与脱敏机制。日志、异常和 API 响应不得包含明文密钥。

## 原子保存与一致性

所有生成操作遵循“先生成、后校验、最后替换”：

1. 在项目目录内创建临时文件。
2. 完成 Base64 解码、图片校验、裁切和排版。
3. `fsync` 临时文件。
4. 原子替换 `cover-base.png` 与 `cover.png`。
5. 最后更新 `project.json` 与主设置镜像。

任一步失败都清理临时文件并保留原封面与原元数据。简介同样只在结构化输出全部校验通过后更新项目文件。

## 错误处理

面向用户的结果或错误需要包含可执行动作。其中 `image_provider_not_configured` 是 `prompt_ready` 成功状态的原因码，不是 HTTP 失败：

- `image_provider_not_configured`：已保存提示词；前往配置或复制提示词。
- `image_provider_unauthorized`：检查图片 API 密钥。
- `image_model_unsupported`：更换支持图片生成的模型。
- `unsupported_image_response`：服务只返回外部 URL，当前仅支持 Base64。
- `image_generation_timeout`：保留提示词和旧封面，可重试。
- `invalid_image_payload`：服务返回的不是受支持图片。
- `cover_font_unavailable`：配置中文字体路径后重新排版。
- `synopsis_generation_invalid`：模型两次都未返回合格结构，可带指导语重试。
- `publishing_asset_write_failed`：保留旧数据并提示检查项目目录写权限。

前端错误只显示当前卡片。生成期间的旧内容继续可见，不用空白骨架替换。

## 测试策略

### 单元测试

- 作品包装上下文只读取允许字段并执行限长。
- 番茄简介结构、标签、字符数和模式校验。
- 无效简介只修复一次，失败不覆盖旧内容。
- 封面提示词包含构图、留白和无字约束。
- 图片 Base64、MIME、字节数与像素数校验。
- 3:4 裁切、768×1024 输出和透明度处理。
- 短书名竖排、长书名换行及缺少中文字体错误。
- 原子保存失败保留原文件。

### API 测试

- 旧项目读取为空结构。
- 生成、编辑和重生成简介。
- 图片未配置时返回 `prompt_ready` 并持久化提示词。
- 假图片提供器生成并下载 PNG。
- 外部 URL 响应被拒绝。
- 重新排版书名不调用模型。
- 两条生成链路的错误互不影响。
- 图片配置密钥被安全存储、返回时脱敏。

### 前端与端到端测试

- 双卡片空状态、窄屏堆叠和成功状态。
- 封面与简介分别生成，当前卡片独立锁定。
- 编辑、保存、复制、下载和带指导语重生成。
- 提示词兜底和“前往配置”入口。
- 失败后旧内容仍可见且可以重试。

测试只使用假的文本与图片提供器，不调用真实付费 API。

## 兼容与迁移

- 旧项目不执行批量迁移；缺少 `publishing_assets` 时按空状态读取。
- 第一次生成或编辑时写入 `publishing-assets/v1`。
- 当前项目更新逻辑必须保留未知和新增的 `publishing_assets`，避免世界、大纲或角色页面保存时丢失作品包装数据。
- 修改书名后不自动调用模型；概览页提示用户使用现有底图重新排版。

## 不在首版范围

- 自动在创建小说时生成封面或简介。
- 一次生成多张候选图。
- 封面历史版本库与版本对比。
- 作者名、平台角标或 AI 标记。
- 自动发布到番茄小说。
- 服务端抓取图片提供器返回的任意外部 URL。
- 为 SQLite 旧项目增加同等作品包装界面。
- 自动生成或测试多个书名。

## 完成标准

1. 文件型项目概览页显示独立封面与简介卡片。
2. 简介能按番茄风生成、校验、编辑、复制和重生成。
3. 封面能生成提示词，并在独立图片模型可用时生成单张 3:4 PNG。
4. 最终封面只有系统叠加的清晰书名，不含作者名或 AI 标记。
5. 图片模型不可用时提示词仍可用，旧封面和旧简介不会被失败请求覆盖。
6. 配置、后端、前端和端到端测试覆盖主要成功与失败路径。
