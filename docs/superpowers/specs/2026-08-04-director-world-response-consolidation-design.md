# 导演与世界响应合并设计

## 问题

当前导演已经决定本章目标、人物行动、场景链、阻力、结果和章末钩子。随后的世界响应阶段再次读取同一份计划，生成世界事件、场景卡和风格提示。实际执行时，导演场景链又会优先覆盖世界响应生成的场景卡，因此形成重复规划、额外耗时和工作台展示歧义。

## 职责边界

- 导演是本章唯一的剧情决策者，产出本章事件计划和场景链。
- 写前准备只校验世界规则、连续性、信息可见性和状态变化是否合法，不新增剧情目标、人物行动或场景。
- 写手直接接收导演场景链，以及校验后整理出的规则边界和相关角色卡。
- 正文确认后，系统再根据实际正文和状态变化推进市场、势力、NPC、任务与隐藏世界状态。

## 流程

`读取大纲与状态 -> 导演规划 -> 写前规则校验与上下文组装 -> 写手 -> 综合审稿 -> 确认正文 -> 更新世界后台状态`

世界后台状态更新不反向改写已确认正文，只作为下一章的输入。

## 工作台

- 删除独立的“世界响应”生成步骤。
- 将原“准备剧情场景”改为“准备写作上下文”。
- 展示导演产物、规则校验结果、写手实际读取内容和正文确认后的世界状态更新。

## 兼容与测试

- 保留已有世界状态与世界脉冲数据格式，避免破坏旧项目。
- 删除写前世界事件生成调用，但保留确定性校验函数。
- 验证导演场景链原样进入写手上下文。
- 验证正文确认后世界状态仍会推进。
- 验证工作台不再出现独立“世界响应”阶段。
