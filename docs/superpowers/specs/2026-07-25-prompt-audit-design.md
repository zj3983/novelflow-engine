# 提示词诊断与压缩设计

## 目标

在现有提示词工作台中加入独立诊断能力，帮助用户定位提示词过长、重复、变量错误和规则冲突。

诊断不参与章节生成，不自动修改或保存提示词。默认不调用大模型。

## 范围

第一版覆盖两类输入：

1. 提示词模板：检查当前编辑器里尚未保存的模板内容。
2. 真实调用：检查某次实际发给模型的完整用户提示词。

第一版不包含：

- 自动重写提示词。
- 自动保存项目或全局模板。
- 每章生成时自动运行诊断。
- 市场扫榜、文风提取和小说正文审稿。
- 自动或默认调用 AI。

## 页面设计

### 提示词模板

在现有模板编辑器操作区增加“检查提示词”按钮。检查对象是编辑器当前内容，包括尚未保存的修改。

诊断结果显示在编辑器下方，不覆盖原文。用户切换模板或继续编辑后，旧结果标记为“内容已变化”，需要重新检查。

### 真实调用

在真实调用详情的完整提示词区域增加“检查这次调用”按钮。检查对象是已记录的 `user_prompt`，结果只用于查看。

### 结果结构

结果保持简短，只显示：

- 总字符数、有效行数、重复字符估算、预计可减少字符数。
- `必须修`：变量缺失、未知变量、明确冲突等会影响执行的问题。
- `建议精简`：重复句、重复约束、过长模块和可合并内容。
- `正常`：通过的关键检查，不展开成长报告。

每个问题包含问题名称、证据片段、位置、修改建议和预计可减少字符数。问题按严重程度和节省字符数排序。

## 诊断引擎

新增独立的本地诊断模块。模块只接收文本和少量元数据，不读取小说项目、角色卡或章节正文。

### 模板检查

- 检查必需变量是否全部出现。
- 检查是否出现未声明变量。
- 检查同一变量是否被无意义重复。
- 检查空模板、超长模板和重复行。
- 检查互相冲突的明确指令，例如“只输出正文”与“输出分析报告”。

模板变量沿用现有 `prompt_templates.py` 的变量解析和校验规则，避免建立第二套语法。

### 真实调用检查

- 统计总长度和有效行数。
- 识别完全重复和规范化后重复的句子。规范化只去除首尾空白、连续空白和列表序号，不改写词义。
- 识别同一约束在多个区块中重复出现。
- 按 Markdown 标题拆分区块，统计各区块长度占比。
- 标记异常长区块，但不凭长度直接判定错误。
- 识别明显冲突的输出格式、视角、目标字数和是否输出说明等指令。

第一版不做模糊语义相似度判断，避免误删含义相近但职责不同的约束。

## API

提供本地诊断接口：

`POST /prompt-audit`

请求字段：

```json
{
  "mode": "template | final_call",
  "content": "待检查提示词",
  "template_key": "writer",
  "required_variables": ["output_section"]
}
```

`template_key` 和 `required_variables` 仅在模板检查时使用。

响应字段：

```json
{
  "schema_version": "prompt-audit/v1",
  "summary": {
    "characters": 12000,
    "lines": 96,
    "estimated_redundant_characters": 1800,
    "estimated_reduction_percent": 15
  },
  "must_fix": [],
  "suggestions": [],
  "passed_checks": []
}
```

接口不写文件、不调用模型、不保存结果。

本地诊断允许的最大输入为 200,000 个字符。

## AI 深度诊断

第一版同时提供“AI 深度诊断”按钮，但必须由用户主动点击。它不在页面加载、模板保存或章节生成时自动运行。

接口：

`POST /prompt-audit/deep`

请求包含原提示词、本地诊断结果和诊断模式。AI 只补充语义重复和语义冲突，不重新统计字符、变量和区块。

AI 深度诊断满足：

- 使用本地诊断结果作为输入，避免让模型重新做机械统计。
- 只分析语义重复和约束冲突。
- 输出沿用同一结果结构。
- 不自动改写和保存。
- 单独显示调用模型、耗时和消耗。

AI 输入上限为 80,000 个字符。超过上限时提示用户先按本地诊断精简，不截断调用。响应增加 `runtime` 字段，包含 provider、model、elapsed_seconds 和 prompt_characters。

## 错误处理

- 空内容：返回 `content_required`。
- 本地诊断超过 200,000 字符或 AI 深度诊断超过 80,000 字符：返回明确错误，不截断后假装完整检查。
- 模式错误：返回 `invalid_prompt_audit_mode`。
- 页面请求失败：保留编辑器内容，只显示诊断失败。
- 诊断结果对应的文本已变化：页面标记结果过期。

## 测试

### 后端

- 模板变量缺失和未知变量。
- 完全重复和规范化重复。
- 明确冲突指令。
- Markdown 区块长度统计。
- 空内容、非法模式和长度上限。
- 诊断接口无文件写入和无模型调用。
- AI 深度诊断只在显式请求时调用一次模型，并返回运行信息。

### 前端

- 能检查未保存的模板内容。
- 模板修改后旧结果显示过期。
- 真实调用可以单独检查。
- AI 深度诊断需要用户主动点击，并显示模型、耗时和输入字符数。
- 三类结果和字符统计正确显示。
- 诊断失败不影响模板编辑和保存。

## 验收标准

- 用户能在提示词页面检查模板和真实调用。
- 默认诊断不调用任何大模型。
- 用户可以选择运行一次 AI 深度诊断，结果仍保持简短。
- 结果不超过必要信息，不生成长篇报告。
- 不自动修改或保存提示词。
- 不改变现有章节生成流程和提示词内容。
- 同一输入产生稳定、可测试的结果。
