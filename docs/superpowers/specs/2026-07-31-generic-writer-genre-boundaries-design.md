# 通用写手与题材规则分层设计

## 目标

让通用写手提示词只负责跨题材成立的小说写作方法，网游、玄幻、都市等专有知识全部由题材模块按需注入。非网游作品不得再收到玩家、NPC、面板、掉落、交易行等网游语汇或写法。

## 当前问题

当前正文提示词虽然已经拆成输出、本章方向、连续性事实、角色和正文写法五块，但通用写法与网游补充仍有交叉：

- 通用层出现面板、后台规则、NPC、交易流程等网游表达。
- 同一写法在系统提示词、正文写法、章节治理和题材方法中重复出现。
- 禁止项多于正向写法，模型容易先想着避错，再写出僵硬正文。
- 部分检查词经过结构化上下文进入正文，诱发说明句和报告腔。

## 分层方案

### 1. 通用写手基础层

通用层只保留所有小说类型都成立的九条正文方法：

1. 人物行动由过往经历、当前利益和性格共同推动。
2. 配角有自己的目的、判断和应对，不只负责给主角递信息。
3. 重要冲突、转折和结果用完整场景演出，不用旁白概述。
4. 对话符合人物关系、场合和当时目的，并改变信息、态度、关系或下一步行动。
5. 情绪通过动作、停顿、语气、回避和选择表现，少用抽象情绪标签。
6. 设定跟随人物正在处理的事情自然出现，不集中讲解。
7. 句子按动作和说话需要自然变化，理由、条件和结果应当说完整。
8. 具体动作、物件和现场后果优先于抽象判断和总结。
9. 每个场景结束时，人物处境、关系、信息或目标至少有一项发生可见变化。

通用层不出现任何题材名词，也不规定固定爽点数量、固定五感数量、统一八成断章、短段配额等机械指标。

### 2. 题材写法层

题材模块负责该类型独有的叙事常识、语言和读者预期。

网游题材单独包含：

- 玩家、NPC、怪物和游戏身份的称呼边界。
- 面板、等级、属性、技能、装备和状态变化的展示方式。
- 任务、前置任务、掉落、背包堆叠和奖励逻辑。
- 交易行、游戏货币、寄售、市场供需和现实兑换边界。
- 越级战斗、仇恨、刷新、组队和职业配合。
- 虚拟现实中的操作与感官方式，禁止出现鼠标、光标等错误操作。
- 游戏线与现实线的状态切换。
- 隐藏能力和异常掉落的信息可见性。

其他题材继续从各自的类型模块提供力量体系、社会规则、题材节奏和专有语言，不共享网游补充。

### 3. 本书规则层

本书层只保存该作品自己的事实与偏好，例如主角性格锁、叙事人称、特殊设定、禁写内容和用户临时要求。它不得重新定义题材通用规则，也不得把某本书的名词写入全局提示词。

### 4. 本章输入层

本章方向、连续性事实、相关角色卡和场景要求继续按需提取。写手只看到本章相关内容，不读取完整世界观、完整角色库或其他题材规则。

## 提示词组装顺序

最终写手提示词保持以下顺序：

1. 只输出正文的输出契约。
2. 本章目标、阻力、变化和结尾状态。
3. 本章必须遵守的连续性事实。
4. 本章实际出场角色及其关系、目的和说话方式。
5. 精简后的通用正文执行卡。
6. 当前小说类型的题材写法。
7. 本书专属规则和用户本章指令。

后面的具体规则覆盖前面的默认写法，但不能突破连续性事实。

## InkOS 参考边界

采用 InkOS 中跨题材有效的思想：人物行为由经历、利益和性格共同决定；配角保持独立目的；高潮现场演出；设定进入行动；不同角色保持语言区别。

不采用以下内容：固定看点频率、统一的八成断章、强制感官数量、固定短段配额、冗长写前检查表，以及重复出现的写作宪法与代入感清单。

由于 InkOS 使用 AGPL，本项目以重新组织和改写原则为主，不复制大段原文；如保留极短且不可替代的原句，应记录来源。

## 实现范围

- 精简 `orchestrator.py` 中通用 `_writer_craft_section()`。
- 审查系统提示词、章节治理和写作包中的题材泄漏。
- 把网游正文方法集中到现有网游题材模块，由 `is_game` 或题材类型选择后注入。
- 保留现有五块提示词模板骨架，不增加新的生成阶段或模型调用。
- 提示词面板继续显示模板、上下文模块和最终实际调用。

## 验证标准

1. 通用写手方法不包含玩家、NPC、面板、等级、掉落、背包、任务、交易行、游戏货币等网游词。
2. 玄幻、都市和其他非网游项目的最终写手提示词不包含网游方法。
3. 网游项目仍能获得完整网游方法，并且只注入一次。
4. 通用写法明显短于当前版本，不存在同义规则多处重复。
5. 正文输出契约仍要求只输出连续小说正文。
6. 不新增 Agent、审稿阶段或额外模型调用，生成耗时不增加。

## 测试

- 单元测试检查通用正文执行卡的内容和长度。
- 参数化测试覆盖网游、玄幻和都市提示词的题材隔离。
- 测试网游规则只出现一次。
- 保留现有写手提示词模板、项目覆盖和实际调用记录测试。
- 用一个网游项目和一个非网游项目生成提示词预览，检查面板展示与最终调用一致。
