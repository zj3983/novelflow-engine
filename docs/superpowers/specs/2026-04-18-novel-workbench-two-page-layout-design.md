# 小说工作台两页式改版设计

日期：2026-04-18

## 目标

当前小说自动演化工作台把写作输入、章节生成、故事状态、API 配置、模型配置、代理策略混在同一个页面里，导致两个问题：

1. 视觉层级混乱，页面像“拼起来的功能面板”，没有稳定主任务。
2. 写作与配置耦合过深，用户在创作过程中会被大量系统设置打断。

本次改版的目标是把产品调整成更接近创作软件的结构：写作页面专注“创作与章节推进”，配置页面专注“运行参数与模型连接”。页面拆分后，主工作流更清晰，后续继续迭代故事库、导入、批量生成等功能时也更容易扩展。

## 设计结论

本次采用“两页式”结构：

1. 写作工作台
2. 配置中心

写作与配置彻底分离，配置修改采用“统一保存”模式，不使用“即时生效”模式。

## 参考依据

本次结构参考 InkOS Studio 的信息架构思路，而不是直接复刻其界面样式。

参考点如下：

1. 固定左侧导航，负责模块切换。
2. 中央只承载当前任务，不把系统配置塞进核心创作区域。
3. 配置页是独立的控制台，而不是创作页面的附属抽屉。

本项目会保留自己的小说创作语义和页面内容，不照搬 InkOS 的命名和布局细节。

## 信息架构

### 顶层模块

左侧导航固定包含两个一级入口：

1. 写作工作台
2. 配置中心

### 页面职责

#### 写作工作台

只承载与故事创作直接相关的内容：

1. 书籍目录导入
2. 大纲输入
3. 导演补充
4. 角色输入与关系编辑
5. 当前章节预览
6. 历史章节查看
7. 生成下一章
8. 回滚章节
9. 分叉故事
10. 打开其他故事
11. 故事状态与代理运行状态展示

#### 配置中心

只承载系统配置与运行控制：

1. 全局 API 配置
2. 单代理 API 覆盖
3. 模型配置
4. 代理运行模式
5. 温度
6. 新角色策略
7. 测试连接
8. 保存配置

写作工作台不再直接展示 API/模型输入表单，只允许通过跳转按钮进入配置中心。

## 页面布局设计

### 通用骨架

整个前端改为三段式布局：

1. 左侧固定导航栏
2. 中央主工作区
3. 页面顶部轻量标题条

不再使用当前四宫格式的平铺仪表盘布局。

### 写作工作台布局

写作工作台采用三栏结构，但视觉重心集中在中栏。

#### 左栏：创作输入

用于准备故事和维护创作输入。

包含：

1. 导入书籍目录
2. 大纲输入框
3. 导演补充输入框
4. 角色卡列表
5. 添加角色按钮

设计要求：

1. 左栏宽度稳定，适合持续编辑。
2. 角色卡采用可折叠列表，避免角色多时无限拉长页面。
3. 导入结果显示为安静的辅助面板，不抢主视线。

#### 中栏：章节工作区

这是整个页面的核心区域。

包含：

1. 当前故事标题与章节信息
2. 生成下一章主按钮
3. 回滚章节次按钮
4. 当前选中章节正文
5. 章节摘要、节奏、下一步提示

设计要求：

1. “生成下一章”是页面最高优先级操作。
2. 正文区域使用更接近阅读器/编辑器的排版，而不是后台数据卡片。
3. 当前章节内容必须在页面打开后第一时间被看到，不需要在多个卡片之间找。

#### 右栏：故事状态

用于展示上下文与管理操作。

包含：

1. 当前故事 ID
2. 当前章节号
3. 父故事/分叉信息
4. 代理运行状态
5. 最近运行事件
6. 历史章节列表
7. 故事切换列表
8. 删除当前分支故事

设计要求：

1. 右栏视觉降权，作为辅助区。
2. 历史章节与故事列表要清楚区分，避免两个列表混在一起。
3. 分叉和切换操作都留在右栏，不侵入正文区。

### 配置中心布局

配置中心采用纵向分组卡片布局。

#### 分组一：全局默认

包含：

1. 全局 API Key
2. 全局 Base URL
3. 全局默认模型

#### 分组二：代理覆盖

分四个子卡片：

1. 角色代理
2. 导演代理
3. 写作代理
4. 记忆代理

每个子卡片包含：

1. API Key
2. Base URL
3. 模型

#### 分组三：运行策略

包含：

1. 代理模式
2. 温度
3. 新角色策略

#### 分组四：连接与保存

包含：

1. 测试全局连接
2. 测试单代理连接
3. 保存配置
4. 未保存更改提示

## 交互设计

### 导航行为

左侧导航切换页面时，不销毁全局应用壳。

要求：

1. 从写作工作台进入配置中心后，再返回工作台时，当前草稿状态保持。
2. 配置中心保存成功后，返回工作台时不需要重新手动刷新整个页面。

### 配置保存策略

采用“统一保存”模式。

行为如下：

1. 用户在配置中心编辑任意字段时，只修改前端表单状态。
2. 用户点击“保存配置”后，才统一提交到后端。
3. 若用户离开页面前存在未保存更改，页面顶部显示提醒。
4. 测试连接按钮可以直接读取当前表单值进行测试，不要求先保存。

### 写作工作流

标准工作流如下：

1. 在写作工作台导入书籍目录或手动输入大纲。
2. 调整角色与导演补充。
3. 点击“生成下一章”。
4. 中栏显示当前章节内容。
5. 右栏查看历史章节、运行状态与故事分叉。

工作台内不再出现配置表单，避免打断创作节奏。

## 状态与数据边界

### 前端状态边界

#### 写作工作台持有的状态

1. 当前故事草稿
2. 当前章节选择
3. 当前故事详情
4. 故事列表
5. 生成中的 UI 状态

#### 配置中心持有的状态

1. 当前配置表单草稿
2. 已保存配置快照
3. 测试连接状态
4. 未保存提示状态

写作工作台和配置中心之间只共享“已保存配置快照”，不共享临时编辑态。

### 后端边界

本次不重做后端数据结构。

保留现有接口：

1. `/runtime-settings`
2. `/runtime-settings/test`
3. `/stories`
4. `/stories/{story_id}/generate`
5. 其他故事操作接口

本次改版只重组前端页面、路由与状态流，不改后端契约。

## 视觉设计方向

### 总体气质

整体界面要从“功能拼盘”改成“创作工作台”。

关键词：

1. 稳
2. 清晰
3. 有编辑器感
4. 有小说项目自己的气质

### 视觉原则

1. 使用固定左侧导航，形成稳定骨架。
2. 中央区域保留最大留白，突出正文与创作操作。
3. 统一卡片样式，避免同一页面出现太多风格不一的区块。
4. 降低高饱和色使用频率，只把强调色留给主按钮、状态点和关键操作。

### 推荐风格

推荐视觉方向：

1. 暖灰浅底
2. 深色正文
3. 墨蓝或琥珀作为强调色
4. 标题更像出版编辑系统，而不是运维后台

### 具体样式约束

1. 左侧导航：深一点的背景层，与主区形成明显分隔。
2. 主按钮：统一高亮，避免多个主按钮同时竞争。
3. 辅助按钮：用描边或弱底色。
4. 正文区：提升行高与段间距，强调阅读体验。
5. 状态区：使用小标签和短说明，不使用大段提示文本。

## 组件改造建议

### 保留并重组

以下组件优先保留，但会重新归位：

1. `BookImportPanel`
2. `BookLibraryBrowser`
3. `ChapterBundleView`
4. `StorySidebar` 内部的角色编辑逻辑

### 需要拆分

当前 `StorySidebar` 职责过重，需要拆开。

建议拆为：

1. 创作输入面板组件
2. 角色编辑组件
3. 配置表单组件
4. 连接测试组件

### 路由建议

建议新增明确页面路由：

1. `/` 或 `/workbench` 对应写作工作台
2. `/settings` 对应配置中心

## 错误处理

### 写作工作台

1. 生成失败时，只在工作台顶部或正文区上方显示一条清晰错误提示。
2. 不在多个区域重复显示同一个错误。

### 配置中心

1. 测试连接失败时，只在当前测试目标附近展示错误结果。
2. 保存失败时，在页面顶部显示统一错误条。
3. 保存成功时，显示简短成功反馈，并清除未保存状态。

## 测试与验收

### 验收标准

改版完成后，满足以下标准即视为通过：

1. 写作工作台页面不再出现 API/模型配置输入框。
2. 配置中心页面可以完整编辑并保存所有运行配置。
3. 工作台和配置中心之间可以通过左侧导航切换。
4. 工作台刷新后仍可继续查看当前故事与章节。
5. 配置中心改动后，保存前不会污染工作台运行状态。
6. 测试连接支持基于当前表单值执行。
7. 页面视觉层级明显优于当前四宫格布局。

### 测试重点

1. 页面切换后草稿状态是否丢失。
2. 配置未保存时是否有明确提示。
3. 保存后是否能正确影响运行配置。
4. 生成章节、回滚、分叉、打开故事是否仍可用。
5. 书籍目录导入后是否仍能正确载入工作台。

## 范围边界

### 本次包含

1. 前端页面拆分
2. 左侧导航骨架
3. 工作台重排
4. 配置中心重构
5. 样式层级重做

### 本次不包含

1. 新增用户系统
2. 新增权限管理
3. 重构后端存储
4. 新增复杂多项目管理
5. 对小说生成引擎逻辑做大规模后端改造

## 风险与缓解

### 风险一：状态拆分后工作台数据丢失

缓解：

1. 保留当前故事相关状态在页面外层。
2. 配置页面只维护配置草稿，不接管故事态。

### 风险二：拆分后入口变多，用户找不到配置

缓解：

1. 左侧导航固定显示“配置中心”。
2. 工作台顶部保留一个轻量跳转入口，而不是嵌入配置表单。

### 风险三：改版过大影响现有功能

缓解：

1. 第一阶段只重组页面和组件，不改变后端契约。
2. 每个核心交互保留现有调用路径，先确保功能完整迁移，再做视觉精修。

## 结论

本次采用“两页式：写作工作台 + 配置中心”方案，以固定导航承载模块切换，以工作台承载创作流程，以配置中心承载系统设置。该方案能最直接解决当前页面混乱、写作与配置耦合的问题，同时与 InkOS Studio 的信息架构保持一致方向，适合作为当前小说自动演化项目的下一阶段前端基础。
