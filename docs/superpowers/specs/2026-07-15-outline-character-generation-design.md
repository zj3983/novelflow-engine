# 三级大纲与具体角色卡生成设计

## 目标

为文件夹小说项目增加一次生成、分层保存的开书规划流程。一次生成总纲、首个阶段大纲、前五章章节大纲，以及首阶段需要的具体角色卡。后续写作只提取当前章节需要的大纲和人物资料，不把完整资料塞进写作提示词。

## 设计原则

- 大纲管方向，不代替正文。
- 角色卡先回答“这个人是谁”，再补充心理侧写。
- 首阶段建立明确对手，但不提前公开长期反派的全部秘密。
- 不增加常驻大纲 Agent 或角色 Agent；生成器按用户操作调用。
- 生成结果先校验再保存，失败时保留旧版本。
- 用户修改后的内容优先，后续生成不得覆盖已确认字段。

## 用户流程

1. 用户输入小说类型、灵感、书名和一次性补充要求。
2. 用户选择故事方向后，点击“生成大纲”。
3. 系统一次生成总纲、首个阶段、前五章计划和首阶段角色卡。
4. 大纲页分别展示总纲、阶段大纲和章节大纲，所有内容均可编辑。
5. 角色卡页展示具体人物档案；抽象侧写作为高级补充，不占据首屏。
6. 用户保存后开始生成正文。
7. 未规划章节只剩两章时，页面提示“补充后续章节”，但不自动调用模型。
8. 当前阶段快结束时，用户生成下一阶段大纲；生成器读取实际章节总结和当前人物状态，避免继续沿用已经失效的旧计划。

## 生成范围

### 总纲

总纲包含：

- 核心故事
- 主角长期目标
- 主要冲突
- 成长路线
- 结局方向

### 首个阶段大纲

首阶段包含：

- 阶段标题和章节范围
- 阶段目标
- 主要阻碍
- 阶段回报
- 阶段结束时的局面变化
- 阶段对手及其行动升级
- 长期反派在本阶段允许露出的痕迹

### 前五章章节大纲

每章只保存可执行剧情，不写正文措辞：

- 本章目标
- 具体阻碍
- 主角采取的行动
- 局面转折
- 本章可见回报
- 结尾钩子
- 本章需要出场的角色名

章节编号必须连续，角色名必须能对应已有角色卡或同次生成的候选角色卡。

## 角色卡结构

### 一、基本身份

- 姓名、别名
- 性别、当前年龄
- 出生地、来历
- 当前身份、职业或日常差事
- 所属家族、宗门、组织或阵营
- 首次计划出场章节
- 角色层级：主角、阶段对手、重要配角、长期反派、普通角色

### 二、人物来历

- 家庭情况
- 成长环境
- 教育、训练或师承
- 影响至今的重要经历
- 来到故事起点的原因

### 三、当前生活

- 当前住处
- 靠什么生活
- 经济、资源和能力情况
- 当前职务与权力范围
- 眼下最需要处理的问题

### 四、目标与冲突

- 长期目标
- 当前目标
- 行动动机
- 失败代价
- 隐瞒的事情
- 与主线冲突的原因

### 五、具体表现

- 平时如何待人
- 受到压力时怎样决定
- 发生冲突时习惯采取什么行动
- 失败后的反应
- 生气、害怕或放松时可见的动作

这些字段必须描述可观察行为，不能只填“沉稳、谨慎、善良、阴险”等标签。

### 六、说话方式

- 常用称呼和词汇
- 句子习惯
- 对陌生人、熟人、上级和敌人的区别
- 避讳的话题
- 撒谎、生气、放松时的说话变化
- 两至三句符合人物身份和关系的示例对白

示例对白用于确定声音，不得作为正文固定台词反复复用。

### 七、人物关系

每条关系记录：

- 对方姓名
- 关系类型
- 认识经过和时长
- 当前态度
- 共同利益或冲突
- 对对方知道什么、不知道什么

### 八、成长与动态状态

固定档案保存起始缺点、不会改变的底线、阶段成长方向和改变条件。动态状态保存当前位置、当前情绪、伤势、资源、身份变化、最近事件和关系变化。动态状态由章节提交后更新，不覆盖固定档案。

## 双层反派

首阶段必须存在一个具体的阶段对手。阶段对手需要有姓名、身份、利益目标、可用手段、权力边界、对主角的认知和失败后的升级方式。对手不能只是为了作恶，其行动必须符合自身利益。

长期反派可以暂不正面出场，但必须建立简卡，记录：

- 幕后目标
- 与主线秘密的关系
- 当前可调动的力量
- 首阶段允许出现的痕迹
- 暂时不能向主角和读者公开的信息

写作包只能取得当前场景允许暴露的信息，不能把长期反派完整秘密传给正文写手。

## 模块边界

### OutlinePlanningGenerator

一次调用生成三级大纲和角色卡候选。输入只包含开篇方向、小说类型、用户补充要求和必要的题材模块，不读取旧正文。

### OutlinePlanningValidator

检查总纲必填字段、阶段范围、章节连续性、前五章推进、角色引用、阶段对手和长期反派痕迹。校验器不修改文本，只返回具体错误。

### FileProjectStore

负责事务保存 `.webnovel/outline.json`、项目角色卡和生成元数据。先写临时文件，全部校验后替换正式文件。重新生成时保留上一版，失败不破坏现有内容。

### OutlineContextSelector

写章前只提取总纲摘要、当前阶段和目标章节计划。现有 `select_outline_context()` 继续承担这个职责。

### CharacterContextSelector

根据章节计划中的出场人物名提取对应角色卡。主角只取本章需要的固定资料和动态状态；未出场人物不进入写作提示词。

## 新人物处理

章节计划提出新的具名角色时，必须先生成候选角色卡并通过结构校验，之后才能进入正文。普通路人不要求完整卡，但正文不得临时给路人添加会影响后续剧情的重要身份、秘密或关系。

新角色生成不是常驻 Agent，而是“补充后续章节”或用户明确添加人物时的一次性生成操作。

## 页面调整

大纲页增加：

- 生成大纲
- 重新生成
- 补充后续章节
- 生成失败时的字段级问题提示

角色卡页优先展示基本身份、来历、当前生活、目标、关系和示例对白。原有心理侧写与行为侧写移动到高级补充区域。编辑角色卡时可以分别保存固定档案与动态状态。

## 数据兼容

- 沿用 `project-outline/v1` 的总纲、阶段和章节结构，在阶段与章节模型中增加对手痕迹和出场角色字段。
- 现有 `character_profiles` 原样保留，读取时补齐新的具体档案空字段。
- 原有 `personality_portrait`、`performance_profile`、游戏面板和 NPC 边界继续可用，但不再承担基本身份与人物来历。
- 已有用户字段优先，生成和补全不得覆盖非空内容。

## 错误处理

- 模型返回非结构化内容：不保存，提示“生成结果格式错误”。
- 缺少主角、阶段对手或必要总纲字段：不保存并列出缺项。
- 章节编号不连续或阶段范围冲突：不保存并指出具体章节。
- 章节引用不存在的具名角色：要求同时生成角色卡或移除该角色。
- 重新生成失败：继续使用上一版大纲和角色卡。

## 测试范围

- 生成器严格解析三级大纲和角色卡。
- 校验器拒绝缺少阶段对手、章节断号和无卡具名角色。
- 一次保存同时写入大纲和角色卡，任一文件失败时全部回滚。
- 已有角色字段不会被重新生成覆盖。
- 写作包只包含当前章节、当前阶段和本章出场人物。
- 长期反派未公开秘密不会进入正文写作包。
- 旧项目可以读取并编辑，不要求重新生成。
- 页面支持生成、重新生成、补充和手动保存。

## 不做的内容

- 不一次生成整本书所有章节。
- 不自动循环调用模型补大纲。
- 不恢复数据库版 `OutlineAgent`。
- 不让角色 Agent 在每章运行。
- 不用 MBTI、星座或大量问卷代替人物的具体经历和行为。
