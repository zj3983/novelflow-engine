# 网游职业转职树与装备卡设计

## 目标

为网游小说建立可供世界观页面、写作包和章节连续性共同使用的结构化职业与装备数据：

- 所有职业共用 `Lv.10`、`Lv.30`、`Lv.60` 三个转职节点。
- 每条职业路线明确各节点的可选分支、任务、前置条件、能力变化和失败后果。
- 正文中出现的全部具名装备均建立装备卡，不限于主角持有物。
- 稀有、史诗、传说和剧情关键装备可记录类似 DNF 装备文案的描述、来历与套装背景。
- 写作阶段使用这些数据约束等级、职业、装备属性和物品归属连续性。

本功能仅对网游类型启用。非网游小说沿用现有力量体系和器物展示。

## 方案选择

采用扩展现有结构化世界观的方案：职业数据继续归属 `power_system_spec`，装备卡归属 `world_blueprint.equipment_cards`。不在前端解析自由文本，也暂不拆出独立职业库或装备库。

这样能复用当前世界观补全、项目存储、写作包和世界观页面，同时保持数据是单一事实来源。

## 职业数据

### 统一转职节点

`power_system_spec` 增加统一的 `class_advancement_tiers`：

1. `Lv.10 正式转职`
2. `Lv.30 职业分支`
3. `Lv.60 传承职业`

每个节点包含：

- `level`：固定为 10、30 或 60。
- `name`：节点名称。
- `purpose`：该节点在成长循环中的作用。
- `common_requirements`：所有职业共用的进入条件。
- `failure_rule`：任务失败、放弃或延期的统一规则。

网游力量体系只有同时具备三个节点，且等级准确时，才算结构完整。

### 职业路线

每个 `paths` 条目保留职业定位、资源、武器、护甲和战斗循环，并新增 `advancement_tree`。每个节点包含：

- `level`
- `tier_name`
- `options`：该等级可选职业列表。

每个职业选项包含：

- `name`
- `role`
- `requirements`
- `transfer_task`
- `ability_changes`
- `new_resources`
- `equipment_permissions`
- `failure_consequence`
- `next_options`

所有基础职业必须覆盖三个统一节点。隐藏职业可以作为节点内的特殊选项，但不得自行改变转职等级。

## 装备卡数据

`world_blueprint.equipment_cards` 是具名装备的规范列表。装备卡字段为：

- `id`：稳定标识，不因持有者变化而改变。
- `name`
- `aliases`
- `equipment_type`
- `slot`
- `rarity`
- `required_level`
- `class_restrictions`
- `base_attributes`
- `special_effects`
- `skills`
- `durability`
- `source`
- `current_owner`
- `current_location`
- `first_appearance_chapter`
- `last_update_chapter`
- `status`
- `description`
- `lore`
- `lore_status`：`confirmed`、`rumor` 或 `unknown`。
- `related_characters`
- `related_factions`
- `set_name`
- `set_lore`
- `evidence`

`description` 是简短、有辨识度的装备风味文字；`lore` 记录制造者、历史事件和流转经历。普通装备不强制填写这两项。稀有、史诗、传说和剧情关键装备应优先补全，但缺乏证据时只能标记为传闻或未知。

材料、货币、消耗品和普通任务物品不建立装备卡。只有明确作为武器、防具、饰品或可装备特殊物品出现的具名对象才进入图鉴。

## 数据流

### 世界观补全

网游世界观补全提示词必须要求：

- 生成完整的 `10/30/60` 转职节点。
- 每个基础职业生成对应的结构化分支树。
- 不得只用一串职业名称代替转职任务和能力变化。

保存前执行结构校验。节点缺失或职业路线未覆盖三个节点时，拒绝将其标记为完整力量体系，并在页面提示需要补全。

### 章节写作

写作包根据当前等级注入：

- 当前职业路线。
- 最近一个已完成转职节点。
- 下一个转职节点、可选分支及前置条件。
- 与当前场景、角色和任务相关的装备卡。

写作提示必须遵守装备等级、职业限制、属性、特效、耐久和归属，不得临时改写既有装备能力。

### 章节后处理

章节保存后，从正文和章节状态事件提取装备更新：

- 首次出现的具名装备建立新卡。
- 同名或别名命中的装备合并到现有卡。
- 更新持有者、位置、耐久、状态和新揭示的效果。
- 空值不得覆盖已有事实。
- 每项确定信息保存章节证据。
- 证据不足的来历只能保存为 `rumor` 或 `unknown`。

装备提取失败不阻塞正文保存。失败记录进入工作流日志，并允许后续章节或手动编辑补齐。

## 页面设计

### 职业转职树

世界观页面新增“职业转职树”。三个统一等级节点纵向排列，各基础职业横向展示分支。每个职业选项显示定位、转职任务、前置条件、新增能力和下一阶段去向。

页面不以大段 JSON 或逗号分隔文本作为主要展示。移动端改为单列节点，职业选项在节点内顺序排列。

### 装备图鉴

世界观页面新增“装备图鉴”，使用紧凑装备卡：

- 顶部显示名称、品质和类型。
- 中部显示等级与职业限制、属性、技能和特效。
- 底部显示来源、持有者、首次出现章节、耐久与状态。
- 有描述或来历时显示独立的风味文字区域。
- `rumor` 和 `unknown` 使用明确标签，避免与确认事实混淆。

支持按装备类型、品质和当前持有者筛选。装备卡可编辑；编辑仍走项目存储层，以保证项目 JSON、状态和写作上下文同步。

## 接口与兼容性

- 现有世界观读取接口返回职业树和装备卡。
- 世界观更新接口接受并校验这两个字段。
- 旧网游项目若只有字符串形式的 `branches` 或 `equipment`，继续显示旧内容，同时标记“需要补全”。
- 不从旧字符串自动推断确定属性；补全操作可生成结构化数据。
- 非网游项目忽略网游职业节点校验，不显示装备图鉴模块。

## 错误处理

- 职业节点等级不是 10、30、60：力量体系不完整。
- 基础职业缺少任一节点：力量体系不完整。
- 转职选项缺少任务或能力变化：对应路线标记待补全。
- 装备缺少名称或装备类型：不创建卡片。
- 同名不同物品发生冲突：保留两条候选并标记待确认，不静默覆盖。
- 装备来历与已确认世界事实冲突：拒绝提升为 `confirmed`。

## 测试与验收

### 后端

- 校验完整的 `Lv.10/Lv.30/Lv.60` 统一节点。
- 拒绝缺失、重复或等级错误的节点。
- 校验每个基础职业覆盖三个节点。
- 章节首次出现装备时建立装备卡。
- 同名装备再次出现时更新而不重复。
- 材料、货币、消耗品和普通任务物品不建卡。
- 空值不覆盖已有装备事实。
- 来历状态正确区分确认、传闻和未知。
- 写作包只带入相关职业节点与装备卡。

### 前端

- 世界观页完整显示三个转职节点和各职业分支。
- 缺失结构时显示“需要补全”，不展示伪完整职业树。
- 装备卡显示限制、属性、特效、归属和章节证据。
- 有来历的装备显示风味文字；普通装备不出现空白来历区。
- 类型、品质和持有者筛选有效。
- 非网游项目不显示网游职业树和装备图鉴。
- 360px 宽度下无横向溢出、文字遮挡或卡片嵌套。

## 非目标

- 本次不实现独立装备交易、强化或拍卖行操作界面。
- 本次不为每件普通白装自动生成故事。
- 本次不允许不同职业使用不同转职等级。
- 本次不把材料、消耗品和任务物品混入装备图鉴。
