# 伏笔与角色记忆设计

## 目标

让长篇小说中的伏笔和人物变化有唯一、可见、可编辑的记录位置，并确保下一章生成时只读取真正相关的内容。

## 伏笔账本

`state.json.foreshadowing` 是全书伏笔的唯一数据源。每条伏笔记录正文中的具体未解事实，而不是抽象主题。

字段包括：伏笔内容、首次出现章节、最近推进章节、状态、预计回收方式和实际回收章节。状态沿用 `open`、`reinforced`、`resolved`、`expired`。

章后记忆阶段把本章 `unresolved_threads` 与账本合并：新线索新增，已有线索更新最近推进章节；某章没有提到伏笔时保持未解决，只有正文提供明确回收证据或作者手动操作时才能标记为已回收。

下一章写作包最多读取 8 条相关的未回收伏笔，优先选择最近推进、与当前大纲或出场人物有关的条目。完整账本不直接塞进提示词。

## 角色记忆

角色卡分为两层：

- 稳定档案：姓名、年龄、来历、职业、性格、说话习惯、能力边界、长期目标和核心关系。它不会每章自动改写。
- 章节动态：沿用现有现实线/游戏线状态，并记录最近一次出场章节和带章节号的变化证据。位置、目标、身体、知识、持有物和关系等结构化状态只接受明确的状态变更，不从正文概括中猜测。章后记忆不改稳定档案。

写作前按本章大纲中的出场人物提取角色卡；主角始终读取，其他人物按需读取。模型不会收到全部人物卡。

## 页面位置

在现有“大纲”页面增加“伏笔”页签，显示未回收和已回收伏笔，并支持编辑状态和回收计划。角色卡仍在“人物”页面显示，稳定档案与当前动态分区展示，不新增页面。

## 兼容与迁移

旧伏笔记录缺少新增字段时使用默认值，不破坏现有项目。对当前项目，把最近章节摘要中的未解线索合并进伏笔账本。已有角色卡保持原值，只补充最近出场章节和变化证据，不强造新的状态容器。

## 验证

后端测试覆盖伏笔新增、去重推进、缺席不自动关闭、明确回收和写作包限量读取；角色测试覆盖稳定档案不被章后更新覆盖。前端测试覆盖大纲页伏笔展示、编辑和人物页分区展示。
