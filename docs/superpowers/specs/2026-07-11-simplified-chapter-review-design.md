# 简化章节审稿设计

## 目标

把当前重复、冗长的章节审稿收敛为一份可执行报告，降低生成耗时，避免多个审稿器对同一问题重复判断。

## 默认审稿结构

默认只保留三类检查：

1. 硬伤检查：设定冲突、人物错位、题材污染、时间线或数值冲突、字数异常。
2. 正文检查：语句是否通顺、对话是否自然、剧情是否推进、章末是否留下具体行动。
3. AI味检查：报告腔、抽象总结、固定句式、重复表达和不自然的段首套话。

## 通过规则

- 只有硬伤检查可以阻止章节通过。
- 正文检查和AI味检查默认给出修改建议，不自动触发整章重写。
- 同一问题只保留一次，以严重程度和可修改性排序。
- 默认最多返回五条主要问题；没有明确修改办法的问题不进入主要报告。
- 字数不足、题材污染、角色或世界状态矛盾仍属于阻断问题。

## 运行流程

生成正文后只运行一次本地合并审稿。现有细分检查器可以作为内部信号源，但由统一聚合器去重、归类和裁决，不再让读者 Agent、编辑 Agent、审稿 Agent 分别决定是否重写。

默认流程为：

`正文生成 -> 合并审稿 -> 硬伤通过则保存 -> 展示最多五条建议`

自动改稿只有在存在硬伤并且用户启用自动改稿时执行。普通语言问题不再触发多轮模型改稿。

## 页面展示

章节页和审稿页统一显示：

- 审稿结论：通过或存在硬伤。
- 三个分类及各自问题数量。
- 最多五条主要问题，每条包含问题、正文证据和修改建议。
- 不再单独展示读者 Agent、编辑 Agent、审稿 Agent、冷读、剧情主线等重复卡片。

AI味检测作为三类检查之一保留，不再另起多张重复卡片。

## 数据兼容

保留现有详细字段，避免旧章节和接口失效。新增一份简化报告作为页面和自动化流程的默认读取结果。旧字段只用于调试和历史兼容，不再控制默认通过状态。

## 异常处理

- 某个内部检查器失败时，其余检查继续运行，并记录一条内部诊断，不把技术错误展示成正文问题。
- 没有审稿结果时显示“尚未审稿”，不能显示空白通过。
- 旧章节缺少简化报告时，由现有详细报告即时聚合，不要求重新生成正文。

## 验证

- 单元测试验证分类、去重、五条上限和硬伤阻断规则。
- 接口测试验证新旧章节都能返回简化报告。
- 前端测试验证章节页只显示一份报告，不再出现三张 Agent 卡片。
- 对修仙和网游各取一章回归，确认修仙不会收到网游审稿建议。
