# 弹性长篇大纲设计

## 目标

当前项目大纲只规划到第30章，只能支撑开篇。新的大纲系统要同时满足两种结果：作品表现好时能够自然扩展到300至500章，表现一般时能够在约150章内完整完结，而不是突然腰斩或遗留大量无用伏笔。

本次设计适用于所有长篇网文，`苟在网游里成神`作为首个迁移项目。题材专用内容仍由小说类型模块提供，弹性大纲本身不写死网游规则。

## 核心结构

大纲分为三层：

1. 长篇总纲：保存核心故事、核心结局、正常完结章数和最大扩展章数。
2. 分卷大纲：保存每卷目标、阻碍、阶段结果、扩展口和收束路线。
3. 章节细纲：只详细规划未来30章，写到剩余10章时再补下一批。

正文写作包只读取长篇总纲的压缩摘要、当前卷和当前章，不加载全部分卷与全部章节细纲。

## 弹性策略

项目增加三种大纲策略：

- `observe`：观察中。默认按核心主线推进，不提前展开远期内容。
- `expand`：扩展。只展开下一卷的继续路线，不一次生成数百章细纲。
- `close`：收束。下一批细纲转入收束路线，并至少保留一卷完成主要人物、阶段反派、现实线和核心谜题。

策略由作者在大纲页手动选择。系统不读取平台成绩，也不自动判断作品表现。

切换策略只影响尚未生成的章节细纲。已提交章节、已有连续性事实和当前角色状态不得被改写。

## 数据结构

沿用 `project-outline/v1` 的总纲、分卷和章节层级，增加可选字段，旧项目无需迁移即可继续读取。

总纲增加：

```json
{
  "core_ending_chapter": 150,
  "extension_ceiling_chapter": 500,
  "current_strategy": "observe",
  "ending_contract": "现实和游戏两条线均完成核心矛盾，混沌之种来源得到阶段性结论。"
}
```

每卷增加一个可选扩展口：

```json
{
  "extension_gate": {
    "continue_route": "开放更大的地图、势力或能力层级。",
    "close_route": "回收本卷伏笔并转入最终冲突。"
  }
}
```

字段含义：

- `core_ending_chapter`：正常版本能够完整完结的位置，不是强制截断线。
- `extension_ceiling_chapter`：允许扩展的参考上限，不要求提前生成对应章节。
- `current_strategy`：当前人工选择的路线状态。
- `ending_contract`：无论是否扩展都必须兑现的结局承诺。
- `continue_route`：本卷结束后作品表现良好时可打开的下一层内容。
- `close_route`：不继续扩展时如何回收伏笔并进入结局。

## 苟在网游里成神的核心版

核心版约150章，分为五段：

1. 第1至30章，灰烬村开局：解决现实急账，完成前三次成长兑现，建立材料和交易渠道，进入主城。
2. 第31至60章，主城立足：完成第一次转职，异常掉落从材料优势转为职业优势，现实收入稳定。
3. 第61至90章，公会冲突：主角在幕后建立队伍和交易网络，击败第一个真正阻断其成长的阶段敌人。
4. 第91至120章，现实异变：游戏能力开始有限影响现实，现实敌人和现实代价进入主线。
5. 第121至150章，校验者真相：找到第一位校验者，解决混沌之种的核心来源，现实和游戏两条线完成核心结局。

第30、60、90、120章设置扩展口。扩展时可依次加入新地图、跨服竞争、公会战争、现实能力体系和全球服务器；收束时则关闭尚未展开的外层设定，沿核心版进入最终冲突。

## 两条状态线

网游题材的每一卷必须分别给出现实线和游戏线的阶段结果：

- 游戏线至少改变等级、职业、技能、地图、势力关系或核心谜题中的一项。
- 现实线至少改变收入、工作、住处、现实关系、现实风险或能力影响中的一项。

大纲只说明阶段变化，具体数值继续由 `game_state` 和 `real_state` 记录。大纲不得直接改写角色当前状态。

## 细纲滚动

- 首次建立大纲时生成核心总纲、全部核心分卷和未来30章细纲。
- 当未写细纲只剩10章时，页面提示补充下一批。
- 生成下一批前读取已提交章节、当前卷结果、连续性状态和当前策略。
- 新细纲从当前事实继续，不重新规划已经写完的章节。
- `expand`只展开当前扩展口后的下一卷；`close`至少生成一个完整收束卷。

## 页面

大纲页增加一个紧凑的长篇策略区，显示：

- 核心完结章数。
- 最大扩展章数。
- 当前策略。
- 当前卷的继续路线和收束路线。
- 已规划章节数与剩余细纲章数。

作者可以编辑总纲数字、结局承诺、当前策略和每卷扩展口。策略使用单选或分段控件，不能依靠自由文本模拟状态。

## 兼容与错误处理

- 旧 `project-outline/v1` 缺少新字段时，默认 `core_ending_chapter` 为现有最大分卷终点，`extension_ceiling_chapter` 与其相同，策略为 `observe`。
- 新字段均为可选字段，不触发旧项目批量迁移；保存大纲时逐步补齐。
- 核心完结章数不得小于当前已提交章节。
- 最大扩展章数不得小于核心完结章数。
- 收束路线不能为空时，页面阻止切换到 `close` 并给出明确提示。
- 生成下一批失败时保留原大纲，不写入半成品。

## 验收标准

1. 大纲可以表达约150章完整结局和最多500章扩展上限。
2. 每个分卷都有继续路线和收束路线。
3. 作者可以手动选择观察、扩展或收束。
4. 策略切换不修改历史章节和既定事实。
5. 写作包只读取总纲摘要、当前卷和当前章。
6. 章节细纲只滚动维护未来30章，并在剩余10章时提示。
7. 旧大纲读取、编辑和保存不报错。
8. `苟在网游里成神`迁移后保留现有前30章细纲，并增加第31至150章核心分卷。
