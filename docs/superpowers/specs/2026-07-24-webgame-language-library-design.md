# 网游语言库设计

## 目标

让网游正文使用玩家熟悉的中文表达，避免把世界设定、服务器实现和交易后台术语直接写进小说。语言库必须按场景选取，不能整库塞进写手提示词，也不能影响其他小说类型。

## 边界

- 世界观继续记录机制事实，例如服务器结构、交易审查和信息权限。
- 网游语言库只负责把事实转换成玩家侧表达，不修改数值和剧情结果。
- 不新增 Agent，不增加独立生成阶段。
- 《魔兽世界》只作为传统 MMORPG 的语言参照，不复制专有剧情、物品或任务文本。

## 结构

在 `genre_types/game_webnovel.py` 中维护语言卡。每张卡包含：

- 场景 ID：登录、任务、战斗、掉落、背包装备、交易、组队副本、公会社交。
- 触发词：从本章计划、场景卡和正文目标中判断是否需要。
- 推荐说法：玩家界面与玩家对话常用词。
- 避免说法：后台、运营、数据和审核语言。
- 写法示例：只保留一到两个“事实转现场”的短例子。

## 选择流程

1. 导演输出剧情事实和场景标签，不输出正文措辞。
2. 写手上下文根据本章场景选择最多三张语言卡。
3. 写手把事实写成角色操作、界面反馈、物品变化和玩家对话。
4. 审稿检查后台词与不符合玩家习惯的流程说明，只重写命中段落。

默认始终加载“基础 MMO”卡；其余卡按需选择。交易章节不加载副本语言，战斗章节不加载完整交易词表。

## 语言口径

- 服务器：服务器、区服、分线、位面、换线。
- 任务：接任务、交任务、任务进度、任务物品、完成、解锁后续任务。
- 战斗：刷新、拉怪、仇恨、抢怪、归属、残血、回蓝、卡位、脱战。
- 掉落：出了、掉了、拾取、战利品、绑定、可交易、掉率。
- 交易：交易行、上架、求购单、一口价、成交、手续费、到账。
- 官方人民币交易：官方交易平台、报价、交易中、已成交、已到账。

避免在正文使用负载分片、承载节点、配方验证、样本判定、平台封存、封存交割、现实结算、字段权限等词。

## 反馈沉淀

用户指出不自然表达时，先保存“原句、原因、改法、所属场景”。同类问题重复出现后，再升级为语言卡规则和回归测试。项目级临时问题不进入全局语言库。

## 验证

- 单元测试覆盖场景选择、最多三张卡、其他题材不加载。
- 提示词测试确认只出现本章相关语言卡。
- 审稿测试确认后台词被拦、正常玩家术语不被误判。
- 用现有网游第一章复核，综合审稿保持通过。
