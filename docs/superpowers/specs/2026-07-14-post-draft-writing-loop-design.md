# 最终正文驱动的写作闭环设计

## 目标

修复当前生成流程中“写前计划、最终正文、下一章状态”彼此不一致的问题，并减少机械修补造成的拼接感。修复后，长期大纲和题材规则负责决定写什么，Writer 负责把场景写出来，Memory Agent 只从最终采用的正文中提取事实，审稿只决定是否需要一次针对性改稿。

本次不新增审稿 Agent，不重写整个编排器，也不增加分段写作。每章固定增加一次 Memory Agent 调用。

## 当前问题

1. 非网游导演提示词没有收到完整 `chapter_seed`，玄幻、仙侠等题材只能依赖压缩后的项目快照。
2. `plot_contract.py` 的阶段窗口和节奏合同写死了网游开局，非网游项目可能读到“现实压力、千倍爆率”等内容。
3. `chapter_summary`、`facts` 和 `ledger_updates` 在写正文前就由计划阶段生成，最终正文修改后仍可能回写旧计划。
4. 审稿只在硬伤出现时触发改稿，AI味和明显对话问题通常只生成报告。
5. `_sanitize_chapter_output` 会自动插入台词、情绪锚点、NPC说明和章末钩子，容易把完整正文改成拼接文本。
6. 写作学习只积累负面意见，没有记录最终采用的修订解决了什么问题。

## 总体流程

```text
项目大纲与题材
  -> 本章连续性包
  -> Director 生成本章计划
  -> 题材化长篇合同与场景模拟
  -> Writer 生成整章初稿
  -> 只做格式和术语清理
  -> 本地审稿
  -> 必要时一次针对性改稿
  -> 选出最终正文
  -> Memory Agent 从最终正文提取状态
  -> 校验并回写摘要、人物、账本和未解线索
  -> 保存章节并生成下一章承接
```

## 模块边界

### 1. 计划输入

`StoryOrchestrator._plan_prompt` 对所有题材使用同一组基础输入：

- 项目大纲和当前章节位置；
- `chapter_seed` 中的上一章事实、当前承接、允许推进和禁止解锁；
- 本章实际出场人物的目标、情绪、关系和当前位置；
- 题材标识和题材插件提供的章节方法。

网游可以追加账本和经济字段，但不能拥有另一套完全独立的连续性流程。非网游提示词不得包含网游术语。

### 2. 题材化长篇合同

`plot_contract.py` 保留统一接口，但把内容分成两层：

- 通用层：章节职责、阶段兑现、因果承接、人物变化、下一章行动；
- 题材层：由当前 `genre` 选择网游、玄幻、仙侠或通用规则。

网游继续使用等级、任务、资源滚雪球等合同。玄幻和仙侠使用境界、身份、势力、机缘、代价等可选维度，但只读取项目已经建立的设定，不自行发明境界名。通用题材只要求本章改变目标、关系、信息、资源或风险中的至少一项。

阶段窗口不再仅按固定章节号决定剧情内容。章节号只提供节奏参考，具体目标优先来自用户大纲、卷纲和上一章 `next_focus`。

### 3. 最终正文记忆提取

新增一个清晰的后置记忆步骤，复用现有 `memory` 模型配置，不新增 Agent 类型。输入只包含：

- 最终采用的完整正文；
- 上一章状态摘要；
- 已知人物名和可修改字段；
- 当前题材；
- 写前事实锁，仅用于识别冲突，不能当作已发生事实。

Memory Agent 返回结构化结果：

```json
{
  "summary": "本章实际发生的事情",
  "facts": [{"text": "已发生事实", "evidence": "正文中的短证据"}],
  "unresolved_threads": [{"text": "仍未解决的问题", "evidence": "正文中的短证据"}],
  "next_focus": "下一章可以立刻承接的动作",
  "character_updates": [
    {
      "name": "已有角色名",
      "emotion": "章末真实情绪",
      "goal": "章末真实目标",
      "location": "章末位置",
      "evidence": "正文中的短证据"
    }
  ],
  "ledger_updates": {},
  "ledger_evidence": {}
}
```

应用规则：

- `summary`、`facts`、人物变化和账本更新均以最终正文为唯一事实来源；
- 带证据的字段必须能在正文中找到对应文本或规范化后的等价文本；
- 只更新已经存在的角色，不能凭记忆提取临时创建角色卡；
- 账本字段必须通过现有账本校验后才应用；
- 写前计划中的 `chapter_summary` 和 `ledger_updates` 只用于对照，不直接回写；
- Memory Agent 失败时，保留最终正文，使用正文截取生成临时摘要，不应用写前计划中的人物或账本变化，并在质量报告中记录 `memory_sync=fallback`。

### 4. 审稿与一次改稿

简化审稿输出仍只展示少量问题，但增加内部字段 `needs_revision`。以下情况触发一次改稿：

- 连续性、设定、数值或篇幅硬伤；
- 明确AI味、报告腔、公式句或抽象总结；
- 明显对话问题，包括短句压缩、理由说不完整、关系尺度错误和多人同声。

其他轻微文风建议不自动改稿。一次改稿后重新审查并通过 `revision_safety` 比较原稿和候选稿，不进行第二轮循环，避免速度继续下降和越改越乱。

### 5. 正文清理器

`_sanitize_chapter_output` 只允许：

- 去除模型前言、标题重复和 Markdown 包装；
- 统一空行、引号和明确的项目术语；
- 清理已确认的后台字段泄漏；
- 执行不改变剧情的安全替换。

清理器禁止新增完整句子、台词、情绪、NPC互动、剧情解释、状态结果和章末钩子。缺失内容交给审稿与一次改稿处理。

### 6. 写作学习

只有候选改稿被 `revision_safety` 选中时，才记录一条正向学习结果：

- 原问题类别；
- 最终采用的修改目标；
- 哪些事实被保护；
- 下次写前应采用的具体方法。

不保存整段审稿报告，不把正文原句长期塞进提示词。学习快照继续限制条数，避免提示词重新膨胀。

## 错误处理

- Director 失败：保持现有行为，章节生成失败，不写入半成品状态。
- Writer 失败：保持现有行为，不调用 Memory Agent。
- 改稿失败：保留初稿并继续后置记忆提取。
- Memory Agent 失败或返回无效 JSON：正文可以保存，但不应用计划状态；质量报告明确显示记忆回写降级。
- 证据校验失败：只丢弃对应字段，不丢弃整份记忆结果。
- 题材插件未知：使用通用长篇合同，不能回退到网游合同。

## 测试范围

### 单元测试

1. 玄幻和仙侠计划提示词包含 `chapter_seed`，且不含千倍爆率、铜币、任务面板等网游专用词。
2. 网游、玄幻、仙侠和未知题材得到不同且无污染的长篇合同。
3. 清理器不会给缺少台词的正文自动添加台词，也不会自动补情绪句和钩子。
4. 简化审稿对硬伤、AI味和对话问题设置 `needs_revision=true`，普通建议不触发。
5. Memory Agent 使用最终候选正文，而不是初稿或写前计划。
6. 写前计划与最终正文冲突时，只回写最终正文中有证据的事实。
7. Memory Agent 失败时不应用计划中的账本和人物变化。
8. 只有被选中的改稿结果进入写作学习。

### 回归测试

- 运行全部 Python 测试；
- 运行前端生产构建；
- 对现有玄幻测试项目生成一章，检查提示词和质量报告；
- 对现有网游项目只生成写作包或测试副本，不改动正式小说正文；
- 生成前后核对数据库章节哈希，确保历史正文不被修改。

## 性能边界

正常章节固定增加一次 Memory Agent 调用。改稿调用仍是条件触发，最多一次。不会恢复分段生成，也不会增加新的审稿 Agent 或循环审稿。

## 完成标准

1. 非网游项目不再读取网游长篇合同。
2. 下一章状态来自最终正文，不来自写前计划。
3. 清理器不再创作正文。
4. 明显AI味和对话问题能够触发一次改稿。
5. Memory Agent 失败时不会污染人物、账本和连续性状态。
6. 全部自动化测试和前端构建通过，现有历史章节哈希保持不变。
