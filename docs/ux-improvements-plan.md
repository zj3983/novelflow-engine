# 前端交互改进计划（修订版）

> Novel Autogrowth Engine Web（`apps/web`）交互体验改进路线图

| 项目 | 内容 |
| --- | --- |
| 初次审计 | 2026-08-17 |
| 本次修订 | 2026-08-18 |
| 当前使用场景 | 本地、单作者为主 |
| 涉及范围 | 前端交互、必要的后端支持、自动化验收 |
| 不在范围 | 品牌升级、国际化、团队协作历史、彻底删除后的恢复 |

---

## 一、当前结论

项目并不是缺少所有交互能力，而是已有能力分散、反馈标准不统一：

- 项目已有回收站、恢复项目、永久删除接口，不应再设计一套“恢复刚才删除”接口。
- 已有 `lib/user-facing-error.ts`，错误处理应继续从这里扩展，不能另建重复的文案中心。
- 已有较多 `role="alert"` 和 `aria-live`，新增 Toast 时不能重复显示同一条错误。
- `ProjectWorkspaceProvider` 已处理并发请求和卸载后的状态更新，重构时必须保留。
- 写作页、大纲页功能较多，主要问题是职责混杂，不是单纯的文件行数过长。
- 弹窗缺少完整键盘操作；大部分编辑页缺少未保存保护和自动草稿。
- 长任务有后端任务记录，应展示真实阶段和进度，不能写未经计算的预计时间。

当前本地基线：

| 场景 | 当前耗时 |
| --- | ---: |
| 单章接口 | 约 0.12 秒 |
| 项目概览 | 约 0.75 秒 |
| 故事概览 | 约 0.64 秒 |
| 190 章项目写作页可操作 | 约 3.2 秒 |

## 二、优先级

### P0：数据安全和操作可控

1. 弹窗键盘操作与焦点管理。
2. 未保存修改保护。
3. 本地自动草稿。
4. 回收站删除后的撤销入口。
5. 错误分类和可重试判断。
6. 有边界的全局 Toast。

### P1：高频操作清晰、顺手

1. 统一按钮忙碌状态。
2. 长任务展示真实阶段和进度。
3. 修正错误页和占位页文案。
4. 导航分组与移动端抽屉。
5. 章节跳转、搜索和长列表优化。
6. 项目搜索与排序。

### P2：降低后续维护成本

1. 按职责拆写作页。
2. 按职责拆大纲页。
3. 增加全局任务入口。
4. 只在确有等待时使用骨架屏。

## 三、P0 实施方案

### P0-1 弹窗基础能力

统一项目内 Dialog，至少支持：

- `Esc` 关闭可关闭的弹窗。
- 打开后聚焦标题、首个输入框或主要操作。
- `Tab` 焦点不能跑出弹窗。
- 关闭后焦点回到触发按钮。
- 打开期间锁定背景滚动，并阻止背景被误操作。
- 提交、删除、生成等操作正在执行时，不允许误触遮罩或 `Esc` 关闭。

**验收**

- 只用键盘可以打开、操作和关闭弹窗。
- 屏幕阅读器能读到标题、说明和错误。
- 忙碌中的弹窗不会因为误触消失。

### P0-2 未保存修改保护

新增统一的脏数据状态：

- `DirtyStateProvider`：记录当前页面是否有未保存修改。
- `useUnsavedChangesGuard`：统一处理离开确认。
- 浏览器刷新、关闭标签页使用 `beforeunload`。
- 项目内部链接、侧栏切换、程序跳转都必须经过同一套守卫。
- 保存成功后立即清除脏状态；保存失败时继续保留。

首批接入页面：

- 项目设置。
- 总纲、分卷大纲和章节细纲编辑。
- 角色卡编辑。
- 新建小说流程。
- 续写导入流程。
- 提示词项目覆盖编辑。

**验收**

- 页面内链接、浏览器返回、刷新、关闭标签页均不会无提示丢失修改。
- 用户确认离开后只跳转一次，不出现循环确认。
- 保存成功后离开不再提示。

### P0-3 本地自动草稿

新增 `useLocalDraft`，作为未保存保护的补充：

- 输入停止 800-1200 毫秒后保存。
- 草稿键包含项目、页面类型、记录 ID 和结构版本。
- 草稿保留 7 天，过期自动清理。
- 页面打开时发现草稿，明确询问“恢复草稿”或“放弃草稿”。
- 正式保存后删除对应草稿。
- 结构版本不兼容时不自动覆盖当前数据。

安全边界：

- 不保存 API Key、Token 等秘密信息。
- 不默认保存整章正文，只保存表单型资料和必要的编辑内容。
- 草稿仅是本机恢复手段，不代替后端正式保存。

### P0-4 回收站删除与撤销

复用现有删除和恢复能力：

- 普通“删除项目”实际移入回收站。
- 删除后显示 8 秒操作提示：“已移入回收站”，并提供“撤销”。
- 撤销直接调用现有恢复接口。
- 提示消失后，用户仍可从回收站恢复。
- 永久删除继续要求明确确认，不提供虚假的撤销。

**验收**

- 删除后可通过提示立即撤销。
- 提示消失后仍可从回收站恢复。
- 永久删除与移入回收站在按钮、文案和确认方式上明显不同。

### P0-5 错误分类

继续扩展 `lib/user-facing-error.ts`，不新建第二套错误文案模块。

标准化结果：

```ts
type UserFacingError = {
  message: string;
  category: "network" | "server" | "rate_limit" | "validation" | "business" | "unknown";
  retryable: boolean;
  code?: string;
};
```

要求：

- 网络断开与超时：说明连接问题，可重试。
- `429`：说明请求过于频繁，可重试，但不承诺具体恢复时间。
- `5xx`：说明服务暂时不可用，并保留错误代码。
- `4xx` 业务错误：优先使用已有中文映射。
- 校验错误：在对应字段或业务面板内显示。
- 旧的 `userFacingErrorMessage` 保留为兼容包装，逐步迁移调用点。
- 请求封装必须保留 HTTP 状态、后端错误码和原始原因，不能全部压成一个字符串。

### P0-6 全局 Toast

Toast 只解决跨页面或短暂反馈，不接管所有页面错误。

适合 Toast：

- 保存成功。
- 项目移入回收站，并提供撤销。
- 后台任务已经提交。
- 跨页面操作完成。
- 网络恢复等短暂状态。

不使用 Toast：

- 表单字段校验。
- 审稿报告、生成失败详情等需要阅读的内容。
- 阻止流程继续的业务错误。
- 页面已经有明确内联错误的同一条信息。

行为规则：

- 普通提示 4 秒；包含操作按钮的提示 8 秒。
- 相同提示短时间内去重。
- 支持 `aria-live`，但不得与现有 `role="alert"` 重复播报。
- 不显示“预计 30 秒”等没有真实统计依据的时间。

## 四、P1 实施方案

### P1-1 统一忙碌状态

- 提取 `BusyButton` 或统一按钮属性。
- 保持按钮尺寸稳定，执行时显示图标和准确动词。
- 阻止重复提交。
- 页面级首次加载使用统一 Spinner；局部更新不遮住整页。

### P1-2 长任务真实进度

- 使用现有任务 ID 恢复轮询，不因刷新重新创建任务。
- 展示后端返回的阶段名称、已完成步骤和进度。
- 没有可计算进度时显示“正在生成正文”等阶段文案，不伪造百分比。
- 只有积累足够历史数据后才显示时间范围，并明确它是估算。
- 失败后显示可读原因、查看日志和重试入口。

### P1-3 错误页与占位页

- 删除“前往新版”等已经过时的文案。
- 错误页提供“重试”和“返回项目”两个明确动作。
- 占位页说明当前没有什么、下一步能做什么，不展示内部实现术语。

### P1-4 导航与移动端

- 项目导航按“写作、设定、管理”分组。
- 移动端使用抽屉，不把全部入口挤在横向导航中。
- 当前页面保持明确选中状态。
- 不改变现有路由，先调整呈现方式。

### P1-5 章节和项目长列表

- 写作页提供章节号直达。
- 支持按标题或章节号搜索。
- 章节数量较多时采用分页或虚拟列表，不一次渲染全部正文信息。
- 项目页支持标题搜索、最近编辑和创建时间排序。

## 五、P2 重构方案

### P2-1 写作页按职责拆分

建议边界：

- `useChapterNavigation`：章节选择、上一章、下一章、直达。
- `useGenerationJob`：单章生成任务及恢复。
- `useContinuousGeneration`：连续生成队列、停止和断点恢复。
- `useCandidateDraft`：候选正文的保留、替换、丢弃。
- `ChapterReader`：只负责正文呈现。
- `GenerationProgressPanel`：只负责过程与任务反馈。
- `ReviewPanel`：只负责审稿结果和人工操作。

重构要求：

- 先补行为测试，再移动代码。
- 保留 `ProjectWorkspaceProvider` 现有竞态保护。
- 不以“每个文件必须少于多少行”作为完成标准。
- 以生成、切章、刷新恢复、候选保留等行为不变作为验收标准。

### P2-2 大纲页按职责拆分

建议边界：

- `OverallOutlinePanel`。
- `VolumeOutlinePanel`。
- `ChapterOutlinePanel`。
- `ForeshadowingPanel`。
- `useOutlineEditor`。
- `useOutlineGenerationJob`。

优先使用页面内 `useReducer` 统一编辑状态；只有跨页面共享确有需要时再引入 Zustand，第一阶段不增加状态库。

### P2-3 全局任务入口

- 工作台顶部显示真实的进行中任务数量。
- 点击后看到任务名称、项目、阶段、开始时间和状态。
- 数据来自后端任务记录，不能只依赖当前页面内存。
- 页面刷新后继续跟踪原任务，不重复提交。

### P2-4 骨架屏边界

- 只用于稳定布局且通常超过 300 毫秒的首次加载。
- 按钮操作和局部刷新继续使用局部忙碌状态。
- 不为了“看起来高级”把短请求全部换成骨架屏。

## 七、验收指标

### 性能

| 场景 | 当前基线 | 第一阶段目标 |
| --- | ---: | ---: |
| 单章接口 | 约 0.12 秒 | 本地 p95 小于 0.5 秒 |
| 项目概览 | 约 0.75 秒 | 本地 p95 小于 1 秒 |
| 故事概览 | 约 0.64 秒 | 本地 p95 小于 1 秒 |
| 190 章写作页可操作 | 约 3.2 秒 | 本地 p95 小于 2.5 秒 |
| 操作反馈出现 | 未统一 | 点击后 100 毫秒内 |

每个指标至少连续测 10 次，记录中位数和 p95；不能用单次最快结果代替。

### 行为

- 未保存保护覆盖首批 6 类编辑页面。
- 删除项目后可立即撤销，也可稍后从回收站恢复。
- 永久删除不会显示不可兑现的撤销。
- Dialog 可用键盘完整操作。
- 刷新生成页面不会重复创建同一任务。
- 同一错误不会同时以 Toast 和内联错误重复展示。

## 八、自动化测试清单

1. Dialog：`Esc`、焦点循环、关闭后焦点恢复、忙碌时禁止关闭。
2. 未保存保护：内部链接、浏览器返回、刷新、关闭标签页、程序跳转。
3. 草稿：自动保存、恢复、放弃、正式保存后清除、过期、版本不兼容。
4. 回收站：删除、提示撤销、回收站恢复、永久删除确认。
5. 错误：断网、超时、`429`、`500`、`422` 和已有业务错误码。
6. Toast：去重、自动消失、操作按钮、跨页面反馈、无重复播报。
7. 长任务：刷新恢复、失败重试、连续生成不重复提交。
8. 响应式：375 像素移动端和桌面端关键流程。

## 九、实施边界

以下内容本轮不要做：

- 不删除现有 `aria-live`、`role="alert"` 和错误码中文映射。
- 不改写 `ProjectWorkspaceProvider` 的并发保护，除非有对应回归测试。
- 不为永久删除提供假撤销。
- 不把所有错误都塞进 Toast。
- 不显示没有数据依据的预计时间。
- 不在第一阶段引入新的 UI 库、请求库或全局状态库。
- 不在浏览器草稿中保存秘密信息或默认保存整章正文。
- 不为了缩短文件而机械拆组件；拆分必须有清楚职责和行为测试。

完成 P0 后再决定是否进入页面重构。这样先解决数据丢失、误操作和失败反馈，再处理结构与性能，避免同时改动过多导致新的回归。
