# PR #45 原项目能力对齐整改计划

状态：PLANNED

计划修订：独立复审 Iteration 1 的六项遗漏已补入本计划；本次仅修订文档，不代表相关能力已实现或验收。复审基线为 `1591230a582ba066452c93d6eee95f601c414b6f`。

Iteration 2 修订：按操作拆分提示词和 Skill 页面，保留作者模板编辑与本书写作能力选择，单列全局管理工具；仍仅修订计划。该轮复审基线为 `4d4ea7d7b49c3783cd291bdb54de372835f76eb5`。

目标：保留四页产品结构，同时恢复原项目中作者实际需要的能力，使新工作台成为现有小说工程的产品入口，而不是一套功能缩水的独立界面。

## 1. 整改结论

当前四页工作台已经复用了原项目、候选正文和确认服务，但页面能力没有完成对齐：

- **作品页**缺少作品详情、出版素材和完整的归档／回收管理。
- **全书规划页**把大量构建任务直接铺到页面上，同时隐藏了原有的分层大纲、伏笔和可编辑规划能力。
- **写作页**保留了主要候选闭环，但缺少章节搜索、复制和清晰的章节状态定位。
- **故事设定页**只从当前状态读取人物，导致角色不全；世界信息被压平成重复的正文摘录；人物稳定设定、当前状态、关系和未来计划没有清晰分开。
- 全局导航只暴露四页和设置，使仍未迁移的作者功能变得不可发现。

整改采用一条原则：**后端继续使用原有工程能力和数据权威，四页工作台通过产品映射完整呈现作者需要的功能。** 不在前端解释 Build Graph、artifact、revision、stale、preflight、provider 等内部概念，也不另建存储、模型路由或调度器。

## 2. 不可变约束

1. 四个主页面保持为：作品、全书规划、写作、故事设定；模型设置保留独立入口。
2. 只修改未确认候选正文。已确认正文可查看、搜索和定位，不在本轮加入历史改稿。
3. 每章必须人工确认；不得接入自动确认或连续自动发布。
4. Canon 硬冲突、规划采纳权威、候选来源复检、revision 校验和确认事务不得放松。
5. 模型调用保持在项目锁外；提交前重新核对源状态。
6. 不调用真实 provider，不修改受保护小说；测试使用合成项目和注入模型。
7. 原作者页面在能力完成迁移并通过验收前继续保留，不能先删路由或统一跳转。
8. 普通页面不得出现内部工程字段、原始诊断、原始 JSON 或完整私密正文。
9. 所有新增写操作必须复用现有服务和版本检查，不允许 React 直接拼装或推断工程状态。
10. 每项代码改动必须能对应本文的页面任务或验收场景。

### A.2 动态世界状态逐项决定

动态局面与静态世界设定分别读取；不能用 Canon 事实列表替代动态状态。以下内容均为只读产品信息，不直接修改模拟状态。

| 原信息 | 作者是否可见／用户文案 | 目标位置和边界 |
|---|---|---|
| 当前世界快照 | 可见：“当前局面”，包括时间、地点、阶段等已记录信息 | 故事设定 → 世界局面；显示对应章节，不冒充历史章节的快照 |
| 按章节响应记录 | 可见：“本章带来的变化”，可选章节并打开正文 | 同上；切换章节必须读取该章记录，不能总显示最新状态 |
| 公开痕迹 | 可见：“已经显露的变化” | 世界局面；写作显示当前章摘要 |
| 后续压力 | 可见：“接下来要面对的问题” | 世界局面及规划衔接摘要，注明已发生／预测，不能把预测当事实 |
| 下一章可见信息 | 可见：“下一章角色可获知的信息” | 写作准备区和世界局面；标明对象、获知渠道和可见章节 |
| 后台变化 | 其中的故事事件可见：“幕后发生的事” | 世界局面；注明角色是否知情，执行流水和运行计数内部化 |
| 隐藏状态 | 有叙事含义的内容可见：“尚未揭晓的信息（作者可见）” | 世界局面；作者可见不等于角色可知，不直接扩展生成时的角色可见范围 |
| 市场状态 | 可见：“市场动向”，包括原有买卖、价格、数量和压力信息 | 网游等适用类型的世界局面；保留单位和来源章节 |
| 内部状态键、随机种子、调度计数、原始对象 | 内部化，不供 Web 渲染 | 后端明确字段映射；未知字段不直接 stringify，也不能伪造用户解释 |

有更多有效记录时提供分页或展开，不因摘要截断而永久丢失可查看的信息。没有记录时显示“暂无记录”，不得以空列表暗示已核验无变化。阶段 0 需登记未能映射的字段及原因。

### B. 继续保留在内部或机器接口的工程能力

- Build Graph 任务、依赖和内部节点状态。
- artifact、revision、stale、validation_failed 等工程字段。
- 原始 diagnostics、capability、preflight、provider/protocol/model 元数据。
- 实际调用组装后的原始 prompt、上下文快照、运行日志和调试数据。作者可编辑的模板及本书 Skill 选择不属于此类；全局安装管理单列为管理工具。
- AI Public API、CLI/MCP 所需的机器结构。

这些能力不能通过“高级模式”重新暴露给普通作者。需要用户处理时，由后端转换为用户文案和可执行动作。

### C. 独立入口

- 模型配置继续使用 `/config`。
- 拆书与章节体检保留独立作者工具，从写作页进入；全局小说类型管理保留 `/novel-types`，从作品页进入。两者不是内部调试或高级模式。
- 写作指令模板为独立作者视图；写作能力库安装／上传／卸载为独立管理工具，从创作要求中的本书写作能力视图可达。使用现有权限，分离管理操作与项目启用开关，不命名为工程高级模式。
- 归档和回收属于作品管理，可在作品页进入独立子视图。
- 内部调试页面保留直达路由，但不进入普通导航。

## 4. 产品数据契约调整

当前通用 `PlanningPart` 和扁平 `StoryEntry` 不足以承载原项目能力。先在后端建立明确的产品投影，再改页面。

### 4.1 作品投影

新增或扩展：

- `BookLibraryItem`
  - 书名、类型、确认章节数、总字数、当前卷、最近更新时间。
  - 当前待办及一个主要动作：继续改稿、继续检查、确认本章、继续规划或开始写作。
  - 归档／回收状态。
- `BookDetails`
  - 故事简介、封面状态、目标篇幅、每章目标字数、作者要求摘要。
  - 当前规划和写作进度的用户文案。
  - 可用动作：编辑资料、生成简介、生成封面、归档、移入回收、恢复。

增加项目小说类型和文风的当前值、可选项及保存动作。复用原项目设置的 `updateProject` / `world_blueprint` 写入路径，由服务端在锁内校验源状态并合并指定字段，不能用前端旧快照覆盖整个蓝图。变更仅影响后续创作，既有规划需重新校验时显示明确待办，不改写已确认正文。全局类型管理继续使用原注册和配置服务，不建立第二份类型目录。

回收站增加“彻底删除”：仅对已回收作品提供，明确说明正文、设定和记录无法恢复，要求输入完整书名并再次执行删除。复用原删除服务；服务端重新核对项目身份、当前书名、回收状态及已有权限／清理限制，不能仅靠按钮禁用。旧页面缺少的校验作为实施任务补入现有边界；本轮计划修订不执行任何删除。

数据继续来自现有项目和出版素材服务。目标字数是创作目标，不映射为模型输出硬上限。

### 4.2 规划投影

以用户概念替换“遍历所有 Build Graph 任务”的做法：

- `PlanningView`
  - 全书方向、结局目标、当前卷、前文衔接、采纳状态。
  - `volumes`: 卷名、卷目标、主要冲突、人物变化、结尾转折、状态。
  - `upcoming_chapters`: 近期 3–12 章的目标、冲突、推进点和相关伏笔。
  - `author_reminders`: 本阶段必须遵守的作者要求。
  - 可执行动作：准备方向、生成／修复规划、保存可编辑字段、采纳当前规划、准备下一卷。

后端可以读取 Build Graph，但不能把节点和字段原样传给普通 Web。规划内容变化后，原采纳结果必须失效；已被正文消费的规划继续受保护。

### 4.3 写作投影

在现有候选闭环上补充：

- `ChapterDirectoryItem`: 章号、标题、确认／候选状态、当前选择、可定位标记。
- 章节目录搜索结果和匹配数量。
- 当前章的阅读／候选／检查／待确认状态文案。
- 正文复制动作；复制只发生在浏览器，不改变项目。
- 历史章节只读；候选允许手改、AI 修改和重新检查。

服务端确认继续校验候选正文、检查结果和源状态的一致性。前端按钮状态不能替代最终校验。

### 4.4 故事设定投影

- `CharacterView`
  - 完整人物名册，而不是只读取当前 state 中出现的人物。
  - 稳定档案、当前状态、已确认事实、人物关系、未来计划分别呈现。
  - 事实来源只使用可靠章节依据。
- `WorldSection`
  - 世界背景、规则、地点、势力等结构化分组和短摘要。
  - 不把完整正文或重复长摘录当作设定内容。
- `ForeshadowView`
  - 未回收／已回收筛选、首次出现、当前计划、相关章节、可编辑状态。
  - 保存时复用现有版本冲突检查。
- `AuthorRequirementsView`
  - 硬要求、篇幅目标和未来创作意图。

已确认事实为只读；本轮只允许编辑未来计划、作者要求和现有服务允许修改的结构化设定。

补充以下契约和动作：

- `RelationshipView`：人物端点、关系描述、作者设定／已确认依据的区别、可编辑字段、保存动作与不透明的编辑凭证。允许新增、修改和保存关系图，复用原 `updateProject` 的 `relationship_graph` 写路径；产品动作在同一项目锁内比较读时版本／内容摘要并提交。发现旧接口没有比较并交换保护时，补在现有服务边界，不另建关系存储。两个页面并发保存必须拒绝后提交的旧内容；确认事实不能通过关系编辑覆盖。
- `DynamicWorldView`：当前快照、选中章节、可选章节、变化摘要和 A.2 中各类产品信息；携带来源、角色知情范围及空状态，不向 Web 返回模拟对象让其解释。只读查看不运行模拟或模型。
- 世界规则增加“AI 补全世界观”动作、进度、可恢复失败和手动修改冲突提示。复用现有世界补全作业；网络工作在锁外，应用前复核源状态。读取／刷新不自动重启补全，失败不覆盖手改。
- 世界规则增加装备图鉴和怪物图鉴产品条目，沿用原网游条件、条目操作与存储；非适用类型不展示，切换类型不删除既有图鉴。原始构建记录与 raw JSON 留在内部。

### 4.5 拆书与章节体检投影

`DissectionView` 包含模式（参考书／本书）、选中章节、报告摘要、分项建议、来源和可用动作。沿用现有 `/book-dissection/reference` 与 `/file-projects/{project_id}/book-dissection/chapter` 服务，报告只读，不自动写入作者硬要求。

“将报告用于重写本章”从写作页工具带回选中的报告建议，经作者确认后进入现有候选 AI 改稿；服务端核对项目、章节及当前正文身份，改稿后旧检查失效并重新检查。不能把过期报告悄悄应用到不同章节／候选。

**明确的产品限制：** 未确认候选允许使用报告改稿；已确认章节保留体检、报告阅读和复制建议，但不允许重写保存，显示“已确认章节暂不支持改写”。这属于本轮历史正文只读范围下的有意限制，不计为已确认章节重写能力已迁入；恢复该能力须另行规划事实重算，不在本轮隐式开放。

### 4.6 写作指令模板与本书写作能力契约（阶段 1 前置）

**模板编辑保留迁移，不作为有意取消的能力。** `WritingTemplateView` 返回模板名称、用途、可编辑内容、占位符说明、本书／全局来源的用户文案、可用动作及不透明编辑凭证。它只包含待编辑模板，不包含真实请求、私密上下文快照、密钥或内部诊断。后端映射来源和检查结果，Web 不解释内部枚举。

- 读取及保存复用 `PromptTemplatesView` 使用的 `fetchProjectPromptTemplates`、`saveProjectPromptTemplate`、`saveGlobalPromptTemplate`、`deleteProjectPromptTemplate` 对应服务；不新建模板存储。
- “保存为本书设置”建立项目覆盖；“更新全局模板”影响使用该全局模板且无本书覆盖的项目，操作前说明范围并确认，不能悄悄覆盖其他项目自定义内容。
- “恢复使用全局模板”删除本书覆盖，不重置全局模板为出厂内容。删除前显示恢复后的来源并确认；失败保留当前编辑内容。
- 保留普通检查和深度检查，复用原检查服务；返回问题、位置、建议和可执行动作。检查不隐式保存模板；可能调用模型的深度检查必须显式触发，读取／保存不自动触发。实施与验收使用注入模型。
- 项目与全局保存分别在现有服务边界校验读时版本／内容摘要，并原子提交；旧接口如缺少并发保护需补齐，不能假定已有。运行继续使用其开始时的配置快照；保存影响后续生成，不追改已确认正文。检查结论绑定被检查的模板内容，编辑后不能显示旧检查为当前结果。

**项目 Skill 选择保留迁移。** `WritingAbilityView` 返回包和模块的稳定标识、名称、用途、当前选择、可用状态、保存动作和不透明编辑凭证。作者看到“本书启用哪些写作能力”，不需要读取文件路径、原始 Skill 文本或运行结构。

- 保存沿用 `updateProject` 的 `enabled_skill_ids`、`enabled_skill_module_ids`，同时提交包／模块选择，保留原根模块、子模块和旧项目缺省语义；不把打开一个包误解释成自动打开所有子模块。
- 服务端验证包／模块存在及归属关系，在项目锁内复核编辑凭证并原子保存；并发变化拒绝覆盖，失败保留待保存选择。包在编辑期间卸载时返回重新选择提示，不保存悬空引用。
- 下一次写作包与提示词必须读取保存后的选择；以注入生成请求证明启用内容进入、禁用内容退出。正在运行的任务沿用已取配置，不在中途变更；保存和刷新不启动生成，也不重写已确认内容。
- 全局安装、路径导入、zip 上传、包及子模块卸载保留在独立“写作能力库管理”工具，复用原服务、允许路径和包校验；不新增权限体系、不放松权限或解压限制、不执行包内脚本。安装后不自动为项目启用。
- 卸载明确展示其全局影响和相关项目启用记录清理范围，需确认；复用现有卸载清理服务，失败按现有事务语义报告，不显示虚假成功。只使用合成包／项目验证，不操作用户真实能力库。本轮不宣称依赖安全审计完成。

这些作者和管理能力均有明确入口，不作为隐藏的旧直达页面完成迁移；实际调用、上下文和 raw diagnostics 继续内部保留。
