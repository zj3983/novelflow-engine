## 点击顺序

1. **开新书**：作品右侧填写书名、类型、故事想法、篇幅和要求 → 开始准备故事 → 选择方向 → 查看／调整规划 → 采纳本卷规划 → 查看候选 → 只确认本章。
2. **体验改稿**：作品里的渡河人 → 继续写作 → 当前第 51 章有冲突，确认不可用 → 我来改写 → 保存改稿 → 重新检查 → 确认。也可以用“让 AI 修改”，弹窗明确说明固定模拟结果。
3. **体验恢复**：顶部演示场景 → 下次检查失败 → 修改并检查 → 查看失败文案与保留稿 → 重试检查。编辑草稿、改稿和页面选择会在刷新后恢复。
4. **确认后续写失败**：检查通过后，顶部演示场景 → 确认后续写失败 → 确认并继续下一章 → 当前章已保存、下一章未开始 → 重试生成。
5. **跨卷**：渡河人 → 演示场景 → 体验卷末 → 准备下一卷 → 查看衔接与规划 → 采纳 → 生成第 51 章候选。第 50 章仍可从设定依据入口回看。
6. **故事设定**：四个标签可切换，人物可搜索；修改后续设定或作者要求，相关候选重新等待检查；正文依据只打开历史章节。
7. **重置**：顶部重置演示 → 确认。只清除本原型的模拟进度。

## 隔离与限制

- 专用存储键 `novelflow.longform.demo.v1`，没有 API 客户端依赖、真实项目读取或模型调用。
- 初始演示书预置 50 章，仅用于体验第 50→51 章流程。**这不构成 60 章真实 API 注入回归**。
- 模拟生成使用固定正文；模拟检查只识别固定冲突句。它不能验证任意作者约束、文本质量或语义一致性。
- 所有模拟书共享同一套示范故事素材；新建书的标题、目标和要求会保存，但生成不会理解这些要求。
- 浏览器存储不是服务端事务。另一个标签页变更后，旧标签页要求刷新，避免继续覆盖。
- 设置页只说明模拟模式。真实配置在阶段 B 复用 #43；原有导入和真实归档等入口未改动。
- 历史正文只读；旧稿在当前候选中可回看。正式版本历史、审查和事实变更绑定属于阶段 B 服务层工作。
- 原始设计为 1487×1058；桌面和窄屏交互有测试，尚无浏览器可视比对证据。
