## 1. 固定目标与范围

**目标：让作者在一个清晰的工作区内，持续完成规划、生成候选、修改、审稿、人工确认、续写和跨卷；失败后能够恢复，已确认内容不被破坏。**

设计基准固定为已选定的第二张写作页面，以及配套的作品、全书规划、故事设定三张设计稿。原始设计保存在 references/ 下：writing.png、books.png、planning.png、story.png。它们是开发与验收依据。

### 本轮范围

- 四个主页面：**作品、全书规划、写作、故事设定**。
- 设置保留独立入口，复用 #43 的模型配置能力。
- **仅修改未确认候选正文**。历史正文支持回看、定位问题；不实现历史改稿及后续事实重算。
- 逐章人工确认。允许“确认本章并继续准备下一章”，不允许自动确认后续正文。
- 保留导入、归档、恢复等已有能力，不扩展这些功能。

### 明确排除

不重做 Build Graph、模型路由或调度器；不新增通用架构、质量评分仪表盘、工程高级模式；不自动发布或确认正文；不调用真实 provider，不修改受保护小说。

**每项改动必须对应下面的页面、操作或验收场景。无法对应的工作不纳入本轮。**

## 2. 阶段与交付门槛

| 阶段 | 实施内容 | 完成标准 |
|---|---|---|
| A：可点击原型 | 使用合成数据串起四页，覆盖正常流程及异常状态 | 作者能够实际点击走完开书、改稿、确认、恢复和跨卷；确认操作方式后进入阶段 B |
| B：实际功能接入 | 复用已有服务，补候选修改与重审、继续写作、产品数据映射 | 同样的页面流程经过真实本地 API 和注入模型完成，模拟成功状态全部替换为真实结果 |
| C：稳定性验收与交付 | 长程回归、失败恢复、页面验收、远端 CI | 完整 Draft PR、运行说明、截图及测试证据齐全，等待独立复审 |

原型与实际页面使用同一组页面组件、产品数据类型；模拟数据通过独立数据适配层提供，避免接入时重新设计界面。

**只在阶段 A 结束时进行一次产品方向确认。阶段 B、C 连续完成实现、测试和修复，不按按钮或小修反复交接。**

## 3. 页面与功能实施

### 作品与开书

- 将现有作品列表改为设计稿布局，显示已确认章节、当前待处理事项和直接继续入口。
- “继续写作”优先进入待确认候选，其次进入尚未完成的规划，最后进入最近确认章节。
- 新建表单包含书名、类型、故事想法、目标篇幅、每章目标字数和作者硬要求。
- 新建默认目标为 90 万字、每章约 3000 字，允许修改；这些是创作目标，不作为模型输出硬上限。
- 扩展现有创建契约，将目标与要求传入既有规划和写作输入。旧项目缺失目标时显示“未设置”，不自动修改历史数据。
- 开书顺序固定为：填写想法 → 准备并选择故事方向 → 查看全书与首卷规划 → 采纳规划 → 开始正文。

### 全书规划与跨卷

- 整合现有大纲与开书构建入口，展示全书方向、分卷目标、近期章节和前文衔接。
- 复用现有分卷、细纲、滚动规划和跨卷发布逻辑，不另建计划存储或调度流程。
- 将“系统完成规划”和“作者采纳当前规划”明确区分；采纳行为绑定当前规划内容，规划变化后不能继续沿用旧采纳结果。
- 本卷结束后，写作页提供“准备下一卷”；进入规划页查看衔接、调整、采纳后再生成下一卷候选。
- 已被正文消费的规划与已确认正文继续受原有保护。

### 写作、候选修改与重审

- 按选定设计实现章节目录、正文阅读区和问题处理栏。目录只滚动自身，不打断正文阅读位置。
- 问题栏显示用户文案、修改建议和可用的原文／章节依据；没有可靠定位时不生成假高亮。
- 新增候选操作：“我来改写”“让 AI 修改”“重新检查”。
- 修改产生新的候选版本，保留旧稿；旧审查结论和旧事实变化不能用于确认修改后的正文。
- 手工保存不隐式调用模型。作者点击“重新检查”后，复用既有审查和事实提取能力；AI 修改完成后执行同样的检查。
- 检查失败或中断时保留改稿，禁止确认未检查正文；重试复用当前候选内容。
- 服务端确认必须核对正文、检查结果及源状态是否一致；前端按钮状态不能代替最终校验。
- 明确硬冲突继续阻断；允许采用的软建议仍需作者明确选择。

### 确认、继续与恢复

- 复用现有确认事务，保持正文、故事事实和确认回执的一致性。
- “确认并继续”按两个步骤执行：先确认当前章，成功后才启动下一章候选。
- 下一章启动失败时，明确显示“本章已保存，下一章尚未开始”，不回滚已成功确认的章节。
- 重复点击、刷新和请求重试不能重复确认或重复启动同一章。
- 不接入会自动确认的旧连续生成服务。新工作区保持每章等待人工确认。
- 持久化并恢复正在生成、等待检查、等待确认和失败状态；恢复时不自动发起付费模型调用。

### 故事设定

- 聚合现有角色、世界、伏笔和作者要求，形成四个标签页。
- 后端区分已写事实、人物表现和后续计划；仅在存在依据时提供章节来源。
- 本轮允许修改后续计划与作者要求，不能直接覆盖已确认故事事实。
- “发现前文有矛盾”用于定位相关章节并说明处理范围，不承诺自动修正历史正文。

## 5. 验收与防跑偏检查

### 必须通过的场景

1. **完整开书**：新建 → 方向选择 → 规划采纳 → 第一章候选 → 人工确认。
2. **候选改稿**：手工和 AI 两条路径均可修改、重审、确认；旧检查结果无法确认新正文。
3. **冲突处理**：硬冲突无法绕过；修改后检查通过才恢复确认。
4. **失败恢复**：生成失败、检查失败、应用重启和确认后下一章启动失败，均有可恢复状态。
5. **防重复与漂移**：双击、刷新、旧页面提交、规划变化均不造成重复写入或错误确认。
6. **跨卷**：保留前卷正文和事实，完成下一卷规划后继续生成。
7. **长程离线回归**：从新建开始，通过实际 API 和注入模型生成并逐章确认至少 60 章，跨越第 50→51 章；中途注入失败和改稿，不用预填 50 章替代此项。
8. **页面验收**：四页关键操作真实可用，桌面与窄屏可操作，目录、编辑草稿和刷新恢复正常；普通页面无工程详情入口。
9. **最终提交验证**：相关 Core/API、页面专项、专用真实 API 联调、构建、类型检查及最终 HEAD 的 Python/Web CI 成功。

长程注入测试证明流程与数据保护；真实模型下的连续性、文本质量和产出速度，保留为另行授权的验收，不提前宣称完成。
